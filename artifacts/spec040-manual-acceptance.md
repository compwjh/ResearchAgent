# Spec040 人工验收案例

以下步骤针对已部署的 `http://127.0.0.1:8500`。浏览器只需要访问本机地址；不要在输入框粘贴密钥、Cookie 或论文正文。

## A. 查看重试与线上 Provider 配置

1. 打开 `http://127.0.0.1:8500/`。
2. 在模型选择器中确认本地模型仍可选，例如 `qwen3.8:27b`。
3. 打开浏览器开发者工具的 Network（只看响应状态，不复制敏感请求头）。
4. 访问 `GET /api/models`，确认返回两个模型组，并能看到 `deepseek:deepseek-flash`。
5. 访问 `GET /api/health` 和 `GET /api/ready`：两个请求都应为 200；`ready=true` 即表示研究运行时可启动。Qdrant warmup 若显示 failed，不影响本 Spec 的 Runtime 验收，应记录为知识库单独问题。

## B. 查看任务运行时观测

1. 在任务/深度研究页面刷新任务列表。
2. 打开任一研究任务的详情或事件流。
3. 当任务正在重试时，应看到“等待重试/下一次重试”以及重试次数；不应看到完整错误堆栈、Prompt 或密钥。
4. 若本地 Provider 瞬态失败且线上回退可用，应先看到本地失败/等待，再看到“切换备用模型”事件，随后看到当前 Provider 变为线上别名或任务继续推进。
5. 若最终失败，应看到稳定错误码和“可重新发送/恢复”提示；不能把等待状态直接显示成已完成。

## C. 事件续接

1. 在任务详情中记录当前事件序号。
2. 临时刷新页面或关闭再打开同一任务。
3. 页面应从上次事件序号继续读取，不重复执行已完成 WorkItem；已完成证据和报告版本不应被覆盖。

## D. 人工判定

- 通过：A、B、C 均满足，且响应中没有密钥、Cookie、Token、完整 Prompt 或隐藏思维链。
- 不通过：任务卡永久停在 `Queued`、重试计数归零、Provider 未注册、页面显示原始异常、或出现敏感信息。
- 说明：人工验收不要求人为制造 Ollama 断电；真实 Provider 200 探针和定向故障注入测试已覆盖自动回退边界。
