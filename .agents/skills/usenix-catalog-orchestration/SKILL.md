# USENIX 目录检索编排

## 定位：编排层，不是执行层

本技能是**编排协议**：决定「检索什么、按什么顺序、失败怎么办」。
**抓取页面、解析 HTML、缓存、provenance 全部由工具（执行层）完成，编排层不接触 HTML，也不发 HTTP 请求。**

| 层 | 负责 | 对应物 |
|---|---|---|
| 编排层（本技能） | 决策：范围、顺序、补齐、降级 | 本文件 |
| 执行层（工具） | 执行：HTTP、解析、缓存、provenance | `search_paper_catalog`、`fetch_paper_detail` |

## 适用范围

- 按研究方向 / 关键词 / 年份检索 USENIX Security 论文元数据。
- 检索结果缺摘要时，补抓论文详情页获取官方摘要。
- 合并 DBLP 等辅助来源补充缺失的书目字段。

**不适用**：下载 PDF、验证 PDF、导入个人知识库——这些属于
`usenix-download-orchestration`。用户选定论文后即切换到该技能。

## 输入契约

只接受来自服务端的检索条件：关键词 / 研究方向、年份列表、来源（usenix / dblp / all）。
**不接受客户端提交的任意 URL、列表页地址、Cookie、密码或 Authorization。**

## 编排决策点

按顺序决策，每步只调用工具，不自行抓取：

1. **确定范围**：从用户输入提取研究方向与年份；年份缺失时向用户确认，不得跨年份猜测。
2. **执行检索**：调用 `search_paper_catalog` 获取候选论文（标题、作者、年份、DOI，摘要可能为空）。
3. **补齐摘要**：列表页通常不含摘要。对**摘要为空**的候选，调用 `fetch_paper_detail`
   抓取其官方 presentation 详情页补摘要。
   - URL 必须是工具返回的官方详情页地址，**不得自行拼接或猜测 URL**；
   - 工具会做白名单校验，非法 URL 直接拒绝且不发起请求；
   - 详情页仍无摘要时，保留空值并按 `abstract_status: missing` 展示，**不得编造摘要**。
4. **补充书目字段**：DBLP 只用于补 DOI、DBLP key 等官方缺失字段；
   **不得用 DBLP 覆盖 USENIX 官方的标题、作者、摘要、关键词**（官方权威更高）。
   无可核对官方摘要的 DBLP-only 记录不展示。
5. **失败降级**：
   - 单个详情页抓取失败 → 跳过该篇，**继续处理其余论文**，不得中断整批检索；
   - 主来源失败但另一来源可用 → 结果为 `partial`，如实报告哪个来源不可用；
   - 所有来源均失败且无可见结果 → 整体 `failed`，报告稳定错误码。
6. **缓存意识**：已完成单元会命中缓存而不发起网络请求。
   重复检索同一范围时不必担心重复抓取，但也不得依赖缓存去「刷新」已失败的数据。

## 固定发现链

1. 只搜索 USENIX Security；其它会议（NDSS / CCS / S&P）尚未接入，
   **不得静默走其它路径冒充**。
2. 从服务端受控年度入口发现 accepted 页面，只接受 `www.usenix.org` 同源、同年份路径。
3. 只跟随 accepted 页面显式给出的 presentation 链接。
4. 摘要与关键词取自官方页面；关键词缺失时保存空列表，**禁止生成**。

## 硬边界

- **搜索与目录同步阶段禁止碰 PDF**：不得探测、请求、下载、临时保存 PDF，
  不得做魔数或页数检查，不得调用下载器或知识库导入器。
- 不读取或保存 Cookie、密码、profile、Token 或完整认证 URL。
- 不绕过验证码、付费墙、登录权限或 robots / 使用条款。
- 不猜测 PDF 文件名，不遍历站点目录，不访问其它会议网站。
- 不向用户返回可替换的下载地址；下载必须走 `usenix-download-orchestration`。

## 停止条件

出现以下任一情况立即停止并向用户说明，不得继续猜测或降级执行：

- 出现非白名单 URL，或要求访问任意根 URL；
- 页面结构发生变化、无法解释，或返回内容与预期会议/年份不符；
- 缺少检索必需的输入（如既无研究方向也无年份）；
- 工具返回无法恢复的错误且无可用缓存。
