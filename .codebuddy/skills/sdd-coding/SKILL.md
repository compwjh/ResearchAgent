## 上下文预算与进度日志（贯穿全流程，必须遵守）

1. **最小读取**：>300 行的文件用 `offset/limit` 取片段，**禁止全量读**；同一文件**不读第二次**；需要回顾时查自己日志里的结论，不重读原文。

## 任务复杂度自评（动手前先判断，决定策略）

你的模型是 `qwen3.8:27b-mlx`（27B，质量优先、但较慢）。
依据实测（`docs/sdd/TOOLCALL_BENCHMARK.md`），不同复杂度应采取不同策略：

**A. 简单任务** —— 单个独立小函数、无并发、无状态、边界清晰（如格式化、解析、简单工具函数）
- 特征：改动 ≤ 1 个文件、不涉及锁/异步/多文件协作、约束 ≤ 5 条。
- 策略：可**建议主会话转派 `code-drafter`**（`deepseek-coder-v2:16b`，实测 3.6s 极快）先出草稿，再由你复核并落盘；或你直接实现但不要过度设计。
- 注意：drafter 的产出**必须复核**（它不支持 tools，且实测会漏约束，如漏掉"冒号前截断"）。

**B. 复杂任务** —— 必须你亲自用 27B 严谨实现，**不要为了快而简化**
- 特征（满足任一即为复杂）：涉及**并发/锁**、多文件协作、状态管理、缓存/淘汰策略、复杂边界与异常、约束 > 5 条。
- 依据：实测显示轻量模型（9b）在复杂任务上会出现**真实缺陷**，27B 才能正确处理。

**复杂任务自检清单（来自实测缺陷，务必逐项确认）**：
1. **锁范围**：是否**在锁外**执行耗时操作（如调用用户函数、IO）？——9b 曾在 `with lock` 内调用用户函数，导致阻塞/死锁风险。
2. **可哈希判断**：用作 dict key 前是否主动 `hash(key)` 测试并捕获 `TypeError`？——注意"元组拼接"本身不抛异常，只有 dict 查找才抛，try 位置不能搞错。
3. **双重检查**：释放锁再重新加锁后，是否检查其他线程已写入（避免重复计算/覆盖）？
4. **资源上限**：缓存/队列是否有容量上限与淘汰逻辑（如 LRU `popitem(last=False)`）？
5. **异常边界**：不可哈希输入、空值、超时等分支是否都不抛异常？

## 硬性约束（违反必返工）

1. **DOM 契约一致**：JS 渲染的 class/id 必须与 CSS 选择器**逐一核对一致**。
   - 历史事故：JS 输出 `model-list-item` 而 CSS 写 `.model-item`，导致整个视图样式失效、退回裸 DOM。
   - 做法：写完 JS 用 Grep 在 CSS 里搜同名选择器确认存在；写完 CSS 用 Grep 在 JS/HTML 里搜同名 class 确认被渲染。
2. **静态资源版本号**：改动 `frontend/app.js` 或 `frontend/styles.css` 后，**必须**同步升 `frontend/index.html` 里的 `?v=N`。
   - 不升会导致浏览器沿用旧缓存，出现"服务端已更新但页面没变"的假故障（曾反复排查三轮）。
3. **XSS**：所有用户输入（如模型别名）一律用 `textContent` / `input.value` 渲染，**禁止** `innerHTML` 拼接。
4. **CSS 作用域隔离**：新增样式带视图前缀（如 `#models-view`），避免污染其他视图；禁止非法声明（如把选择器写进 `padding` 值）。
5. **不扩大范围**：严格限于 spec 范围，不顺手优化；新想法记入 spec「明确不做」或后续 spec。
