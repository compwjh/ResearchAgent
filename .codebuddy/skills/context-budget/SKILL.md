# 上下文预算与进度日志

> 来源：Spec015 Task13 两次子代理超时复盘（`docs/sdd/retro/2026-09-05-task13-subagent-context-budget.md`），并参照 ECC 的 `strategic-compact` / `iterative-retrieval` 理念。
> **核心事实：本地 27B/9B 子代理的失败主因是上下文被前期读取吃满，不是能力不足。**

## 主动压缩五条

1. **最小读取**：>300 行的文件用 `offset/limit` 取片段，**禁止全量读**；能用 `grep -n` 定位就不用 Read 全文。
2. **禁止重复读**：同一文件绝不读第二次；需要回顾时查自己日志里的结论，不重读原文。
3. **结论落盘即弃原文**：读完一块立即把「结论 + 关键行号 + 待用片段」写进日志，上下文中只保留结论，不堆原文。
4. **预算告急先落盘**：判断已用约 70%（或剩余步骤仍复杂）时，先把「当前进度 / 已完成结论 / 剩余清单」写进日志，再做最小收尾。**宁可提前结束并回报剩余清单，也不要硬撑到被中断**（中断会丢失全部未落盘成果）。
5. **单次一事**：一次分派只做一件事（编码 / 写测试 / 写文档 三选一），不要打包。

## 日志进度预测（每条必填）

每条 `## [HH:MM:SS] 步骤 N：…` 日志**必须**增加一行：

- `- 进度：约 X%（依据：<已完成 M/总 K 步，或一句话理由>）`
- **置信度 ≥50% 就给大概数字**，允许 ±20% 误差；**不得因不确定而留空或写「未知」**。
- 进度**单调不回退**；确需下调时必须写明原因。
- 依据优先用可数事实（「已改 2/3 文件」「测试 8/10 通过」「已判定 6/9 项」），其次才用主观估计。

## 中断恢复（重要）

被中断（aborted / 超时）**不等于零产出**。恢复前先查两处：

1. `git status --short`（工作树是否已有部分改动）
2. `.codebuddy/agent-logs/<role>-<spec>-*.md` 末尾（进度与已完成结论）

据此做「续做分派」，把日志中的结论**直接写进新 prompt**，跳过已完成的最耗时步骤（通常是抓数据/读大文件/做设计那几步）。
