# Spec031 复盘：动态模型路由与资源调度

## 本轮关键问题

1. benchmark 只看 HTTP 成功码不足以证明模型返回质量；已改为校验固定 JSON，并记录资源、端口和运行环境 provenance。
2. 压缩 worker 在 durable checkpoint 前执行可选模型抽取，会造成摘要缺段或失败状态被吞掉；已调整为先写屏障，再做可选抽取。
3. 测试 worker 和 mock 状态跨用例残留，导致异步状态与知识库断言随机失败；已加入前后清理和隔离 fixture。
4. 论文评估已持久化选集，但完成事件没有安全投影 ID，前端因此在报告生成前隐藏选集；已补 `selected_paper_ids`，并限制前端只渲染脱敏 ID/计数。

## 保留边界

- 单 Ollama 实例是本 Spec 的实际放行范围。
- 多实例没有第二实例和独立资源证据，继续 NO-GO。
- 不把 Prompt、回答、思维链、主机路径或租约 token 写入路由/事件或前端。

## 可复用经验

- 质量门必须验证业务响应语义，而非只验证 transport status。
- 所有异步 worker 都要有明确的 durable checkpoint 顺序和测试生命周期清理。
- 事件投影应在后端白名单字段中完成，前端不得猜测或拼接持久化详情。
