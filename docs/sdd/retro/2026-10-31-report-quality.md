# Spec030 报告质量收口复盘

日期：2026-10-31。状态：收口复盘；tester 与独立 architect 双签 READY_FOR_USER，Agent 验收与部署闭环完成，用户人工验收待执行。

## 已证实的问题

- 字数、引用 ID 和结构通过，不代表选集相关或比较成立。2,920 CJK 的认证报告因选集偏题被独立评审打回，历史产物保留。
- 查询遗漏独立 topic、聚合 catalog 引用被扩成选集、数量 floor 和 memory-backed 后置写入绕过阈值，共同造成无关论文凑数。修复覆盖主路径和后置持久化，并以真实 MemoryRepository 用例确认拒绝候选不会重新入选。
- “至少1500个中文字符，逐篇分析”被数量标记跨单位匹配；修复既要区分字数，也要保留未支持的文字篇数澄清，不能静默采用默认值。
- 粗粒度 `agent.output.safety` 无法支持有效诊断。增加闭集分类和白名单路径后，真实调用定位到 safe_summary 的禁止字段，并经反馈恢复；未记录原始被拒输出，未放宽安全限制。
- fallback 后模型名及失败后预算快照曾显示陈旧值。持久记录与实际运行必须分别核验，不能凭初始 provider 字段判断未执行回退。
- 产物存在不等于 canonical 读取可用；真实 API 下载、哈希和浏览器版本选择验证发现了仅单元测试不能替代的问题。

## 本轮采取的做法

同范围小切片开发、定向测试、独立复审后才提交和部署；复审阻塞保留，修复后追加结论。真实失败案例与成功的机器产物分别记录，未用旧报告冒充新案例成功。最终回归按冻结候选记录退出码、覆盖率和存量 lint，区分生产代码与仅测试/文档提交。

## 最终结果与保留限制

“安全研究中的实证评估方法”案例已生成3020 CJK、5篇、4比较、5综合发现，三份真实下载/hash与浏览器验证通过，独立内容5/5、readiness10/10及双签已完成。后端最终3476通过/3跳过/82.25%，前端388通过/0跳过。初轮前端隔离环境无法启动Chromium和三项陈旧测试预期均保留记录，最终受控环境回归全通过。认证案例的证据不足状态保留，不重置预算或扩大其原任务范围。

报告仅为摘要级；专家访谈不是终端用户研究，不能声称所有方法类别已全面覆盖。会议/年份在独立元数据中已核对，但报告因模型只看摘要而采取谨慎范围措辞，后续新版本可改进，不改写当前不可变产物。详见[最终双签验收](../reviews/030-report-quality-acceptance-review.md)与[人工步骤](../plans/030/2026-10-31-manual-acceptance.md)。

本地模型列表静态宣称五档与请求能力缓存不一致，已记为既有 Spec026/035 的后续问题；缓存导致当时拒绝仅为推断，不能当成已证实根因。当前可行性案例明确选择线上 DeepSeek/off，未改变 Ollama 局域网部署或研究 Worker 配置。
