## 做对了什么

1. **方向冲突先裁决、后实现**：主会话发现「地图标签」与「左下角分组」两轮澄清冲突时没有擅自恢复已作废方案，而是暂停实现、给出 A/B/C 三选项，等用户明确「按照A」后才把 spec 转已确认。
2. **Gate 2 评审真的拦住了问题**：评审低估了改动面，但强制约束清单 C1–C9（尤其 `state.groupHighlightId` 三护栏、颜色链路收敛、表单搬 DOM 择一、FAB 布局）为后续实现与验收提供了可逐条核对的判据。
3. **主会话读回校验有效**：多次出现子代理「说改了」但实际未落盘、回传被截断、报告元数据不实等情况，均通过 `Read` / diff / `node --check` / 独立 pytest 发现并修正。
4. **实现期缺陷按范围内闭环**：色块=高亮与已有分组可再改色的语义分叉，由架构师裁决为「双入口」而非推翻冻结裁定 5；409 同图重读期间浮层被误收，也通过 `!state.selectedMapId` 保留了「草稿可直接重试」的既有契约。
5. **E2E 用完即清理**：真实服务上新建的 3 个验收分组与节点归属全部删除/还原，落盘请求、响应、实体 ID 与最终状态，未污染用户数据。

## 做得不好的地方

1. **改动面两次低估**：Gate 2 评审列出 9 个文件，实测暴露 `test_frontend_map_palette.py`（442 行 / 16 用例）、`test_frontend_selection_color_palette_ux.py`、`test_frontend_selection_palette_dismiss_on_apply.js`（419 行 node:vm）三个未列文件，导致 20 个失败用例。根因是评审只按「版本号断言」找依赖，没有按「被删 DOM/API 符号」全量 grep。
   - **改进**：以后「删除功能」类 spec 的评审，必须先 `grep -rln '<被删选择器>|<被删函数>' tests/` 生成完整影响清单，再冻结任务拆分。
2. **测试改造的处置原则定得晚**：最初任务拆分只写「改测试」，未写死「禁止删用例 / 禁止 skip / 能力断言必须迁移而非降格为元素存在」，容易让子代理用删除测试换绿。后续已在 spec 补写死 5 条硬原则。
3. **本地档位子代理报告元数据失真**：429 临时换档后，4 份报告出现虚构角色名（`e2e-runner`）、不存在的约束编号（`C12`）、把 E2E 机器步骤冒充人工验收十步、`node --check` 写成 TypeScript 编译、改动清单编造分类、日志占位符未替换。虽经主会话校正，但消耗了额外轮次。
   - **改进**：给本地档位子代理的 prompt 中把「头部四项真实值」写成可直接复制的固定文本，并要求「不得虚构任何角色名、编号、路径」。
4. **E2E 脚本对浮层遮挡考虑不足**：写操作 E2E 两次因浮层 absolute 覆盖画布而点不到节点，最后用 `dispatch_event('click')` 触发事件委托才通过。产品行为正常（用户会先收起浮层），但脚本应预先处理。
