## 原试行规则

> 暂用于已授权的多 Agent 连续任务；多次运行验证后，由用户确认是否转为正式规则，不自动晋级。

- 每个 Spec 复用一份执行记录，维护当前步骤、实际执行者/任务标识、等待条件与下一动作；不为每轮检查新建报告。
- 子 Agent 返回后，在当前可执行轮次内先判定结果并实际启动下一动作，再汇报：通过接下一门禁；失败分派同范围修复；缺少权限或用户选择则明确请求；全部完成则收口并停止相关定时跟进。
- 未完成任务结束回复前，核对是否有已启动的执行者或明确的等待/阻塞条件；“准备分派”不算已启动，不得以汇报代替推进。授权、评审和资源限制仍优先。
- 正常运行等待子 Agent 主动返回，不反复读取日志；定时检查只用于兜底，不将定时间隔作为接续工作的等待时间。
- 连续执行已获授权时，分派后使用 Agent 等待机制保留接续轮次；等待超时不等于任务完成或用户阻塞，不因一次超时就交回。遵守工具等待时限，收到结果后先处理再汇报；不宣称结束回复后主 Agent 仍会自行连续运行。
- 仅在交付完成、确需用户输入/授权、用户要求暂停或客观执行限制时交回；因执行限制交回时写清已启动任务及恢复触发方式，禁止以“正在等待”掩盖无人推进的状态。
- 每完成实质步骤通知用户当前步骤、结果和已启动的下一动作；状态未变化时保持安静。试行记录追加到同一执行记录，记载断档及纠正情况，作为转正依据。
