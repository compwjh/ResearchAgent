# Spec043 Task03：桌面自动建图 MVP 用户旅程与验收清单

> 关联：[Spec043](../../../../specs/043-literature-map-topic-exploration.md) ｜ [Task03](../../task-03-desktop-map-mvp.md) ｜ [v1 接口与持久化合同](./interface-contract.md)
>
> 文档状态：设计旅程，待实现与浏览器核验。当前不构成 API E2E、浏览器成功或部署证据。
>
> **文案标记约定**：本文所有引号中的按钮、提示、状态和错误文案均为“设计约定，待浏览器核验”，不可直接当作当前生产 UI 的实际文案。真实验收时须用浏览器可见文本和真实响应替换。

## 1. 目标、入口与范围

本案例验证一个桌面用户能否从主导航进入“文献地图”，输入主题并创建一张独立地图；在作业尚未全部完成时看到可用节点和阶段状态；查看真实论文 metadata 与来源；独立控制引用/相似两层；保存视图并离开后重开；在用户明确点击后将单篇论文送入既有知识库导入流程。

本案例只覆盖 Task03 的桌面纵向 MVP。它不把地图接口描述成已经部署，也不把既有论文列表、合成节点或 Spec032 的 Claim/Matrix 当作地图结果。

建议验收主题（只是可复现输入候选，不是已跑通样本）：

- 主题：`模糊测试与漏洞发现`；
- 年份：可选 `2024`（也应验证留空表示不限）；
- 会议：可选 `USENIX Security`（仅在选择器提供且已支持时使用）；
- 项目：可选一个当前用户可见项目，或保持未绑定；
- 首批数量：`20`、`30`、`50` 三者之一；默认应为 `30`。

真实执行前须补齐：当前部署地址、构建/资源版本、浏览器、owner 作用域、主题输入、筛选值、map_id、job_id、真实请求/响应及产物路径。不能用聊天 Intake 或内部 API 调用替代主路径。

## 2. 前置条件与证据规则

1. 使用当前部署版本打开应用首页；地址、端口和版本由最终验收时填写，本文不预设服务已启动。
2. 当前用户能够看到主导航和地图列表；若选择项目，项目属于当前 owner 且在项目选择器中真实可见。
3. 只准备一个新的主题建图案例。不要预填假节点，不要把旧地图或 Spec032 产物当作本次创建结果。
4. 验收记录必须区分：
   - 合同预期：来自 Spec043 与冻结接口合同的字段、状态码、错误码和边界；
   - 浏览器观察：真实可见的按钮、提示、等待状态、节点和详情；
   - API 证据：真实请求、响应、实体 ID、最终状态和产物路径；
   - 未验证/阻塞：没有证据时保持该状态，不能写成通过。
5. “查看地图”只读本地已保存数据，不因打开详情、切换图层或重开而隐式下载、联网补数据或启动新作业。

## 3. 主用户旅程（逐步验收模板）

每一步都包含最终人工验收需要记录的六项：操作、点击后提示、是否等待、等待什么、下一步、失败恢复。以下具体文案均是设计约定，待浏览器核验。

### 步骤 1：从主导航进入文献地图

- **操作**：在首页点击主导航“文献地图”，等待地图视图显示左侧地图列表/新建入口、中央图谱区域和可关闭的右侧详情区域（设计约定，待浏览器核验）。
- **点击后提示**：应显示“文献地图”视图标题以及“新建地图”入口（设计约定，待浏览器核验）；已有地图列表为空时应显示空状态，而不是伪造一个节点。
- **是否等待**：是，等待地图列表读取完成；这是本地列表读取，不应触发外部发现。
- **等待什么**：合同预期为 `GET /api/literature-maps` 返回当前 owner 可见地图列表；浏览器记录实际请求状态、列表数量和页面加载状态。
- **下一步**：点击“新建地图”（设计约定，待浏览器核验）。
- **失败恢复**：若视图打不开或列表请求失败，记录页面提示、HTTP 状态和 request id（若有），返回首页重试一次；不得跳到聊天 Intake、内部 API 或使用旧地图冒充成功。

### 步骤 2：填写新建地图主题与可选范围

- **操作**：点击“新建地图”，在主题输入框填写 `模糊测试与漏洞发现`；年份、会议、项目均为可选；数量选择 `20`、`30` 或 `50`，先记录默认值再选择本轮值。
- **点击后提示**：表单应显示主题必填、年份起止合法性、会议/来源可选、项目可空以及数量选项 `20/30/50`（设计约定，待浏览器核验）。不存在“研究目标必填”或“研究计划批准”步骤。
- **是否等待**：否；仅等待来源/会议选项本身（如页面需要读取）完成，不在填写阶段启动建图。
- **等待什么**：若有选择器请求，记录其实际返回和可选项；不能把会议名称直接当作官方认证，来源依据须以后续 node/provenance 为准。
- **下一步**：确认范围后点击“开始建图”（设计约定，待浏览器核验）。
- **失败恢复**：
  - 主题为空或超出长度：保留输入，显示可操作的校验提示（设计约定，待浏览器核验），修正后再次提交；
  - 年份倒置/非法：修正起止年份，不发送不合法请求；
  - 数量不是 `20/30/50`：回到合法选项，不自行输入其他数量；
  - 项目不可见或跨 owner：保持未绑定，不能手动填写 owner/project_id。

### 步骤 3：提交建图并记录稳定身份

- **操作**：点击“开始建图”一次；若有防重复确认，确认提交（设计约定，待浏览器核验）。
- **点击后提示**：应显示“正在创建地图”或等价的提交中状态（设计约定，待浏览器核验），并让用户能取得地图身份和作业身份；合同预期响应为 `202`，包含 `schema_version="literature-map-v1"`、`map_id`、`job_id`、`map`、`job`。
- **是否等待**：是，等待创建请求完成并进入后台作业；不在请求界面等待所有论文和关系完成。
- **等待什么**：记录实际 `map_id`、`job_id`、请求的主题/范围/数量、响应状态和错误对象；确认服务端 owner 来源不是客户端可覆盖字段。
- **下一步**：进入地图工作区，观察阶段进度；离开页面也不能取消后台作业。
- **失败恢复**：
  - 非重试型 `400/422`：保存稳定 `code/message/retryable`，修正输入后使用新的提交尝试；不重复点击造成多个未知作业；
  - 来源/存储 `503`：保留 request id 和可操作提示（设计约定，待浏览器核验），按提示稍后重试；不把空地图写成成功；
  - `409` 幂等冲突：见第 6 节，先核对已有 `map_id/job_id`，不要用同一幂等 key 改换参数继续提交。

### 步骤 4：观察分阶段建图与首批节点

- **操作**：在地图工作区保持当前地图打开，观察作业卡片、节点数和关系层状态；不点击下载、不切到聊天、不发起审批。
- **点击后提示**：阶段提示应按合同语义依次表达“寻找论文 → 补充元数据与引用 → 计算相似关系 → 地图可用”（设计约定，待浏览器核验）。具体文案、图标和百分比必须以浏览器实读替换。
- **是否等待**：是；作业是后台异步的，页面可以在节点出现后继续查看，不能要求固定秒数。
- **等待什么**：优先等待 `GET /api/literature-maps/{map_id}/jobs/{job_id}` 与事件游标返回可观察状态；如页面轮询，记录轮询频率和终态。阶段字段应落在 `discover/metadata/references/similarity/finished` 语义内，不能把“正在处理”写成完成。
- **等待中显示**：应逐步显示已接受节点、引用边、相似边计数和缺失/失败单元（设计约定，待浏览器核验）；节点先出现不代表所有 metadata、引用或相似关系已齐全。
- **下一步**：当至少有一个真实节点可选时，进入步骤 5；作业仍运行时可留在页面观察，不要求阻塞用户。
- **失败恢复**：
  - `429`/来源暂时失败：显示可行动的限流或来源失败提示（设计约定，待浏览器核验），保留已完成结果；按真实 UI 提供的重试动作执行，若当前版本没有重试入口则记录为待补能力，不自行调用未交付按钮；
  - 进程/浏览器离开：重新打开同一 `map_id`，检查原 `job_id` 是否继续/恢复；不得重新创建整图；
  - 作业停止：保留已完成节点和边，记录终态 `stopped`，不把未获取部分伪装成空结果。

### 步骤 5：查看真实论文 metadata、来源与缺失状态

- **操作**：点击一个真实节点（设计约定，待浏览器核验），打开右侧详情；可关闭详情再选择另一个节点。
- **点击后提示**：详情应显示真实的标题、作者、年份、发表来源、摘要、原始关键词、可取得引用数、来源 URL/provenance、下载/索引状态（设计约定，待浏览器核验）。缺失字段应明确显示“缺失/未取得”或等价状态（设计约定，待浏览器核验），不由模型补写。
- **是否等待**：是；等待 `GET /api/literature-maps/{map_id}/nodes/{node_id}` 返回并渲染，本步骤不应触发下载或全文索引。
- **等待什么**：记录 `node_id`、标题、作者数组、年份、venue、abstract/keywords 是否为空、citation_count、source_url、provenance、external_ids、`catalog_paper_id`/`document_id` 是否真实存在；验证来源标签没有把普通 venue 文本冒充官方认证。
- **下一步**：确认详情与图中节点一致后，可进入步骤 6；若要入库，跳到步骤 8 的主动动作。
- **失败恢复**：节点不属于该图、owner 不匹配或详情不可见时应为稳定不可访问错误（合同预期为 `404`）；记录错误并返回图，不切换到其他地图数据。字段缺失应保留缺失状态，不用标题猜作者、年份、关键词或引用。

### 步骤 6：切换引用/相似两层并核对 title-only 依据

- **操作**：在图例或工具区分别切换“引用关系”和“相似关系”开关；必要时点击“适应画布/定位/缩放”（设计约定，待浏览器核验）。若界面展示相似依据，查看 `title_abstract` 或 `title_only` 标签（设计约定，待浏览器核验）。
- **点击后提示**：每层应能独立显示/隐藏（设计约定，待浏览器核验）；引用为有向实线，方向是引用者 → 被引用者；相似为无向虚线。隐藏只改变视图，不删除持久边。
- **是否等待**：通常否；等待本地视图更新即可，不应因开关或重开重新联网。若需要写入偏好，等待视图保存请求完成。
- **等待什么**：验证 `GET graph` 返回的 `layers.citation`、`layers.similarity` 状态和边集合；验证 `PATCH /{map_id}/view` 的 `layers` 只改变开关，不改变 node/edge 身份。若相似不可用，等待其状态显示 `waiting/running/partial/unavailable` 的真实映射。
- **下一步**：记录两层均开启、仅引用、仅相似、两层关闭四种视图结果；若详情/图例给出 basis，再记录对应 edge 的 `basis` 与 `model_version/content_hash`。
- **失败恢复**：
  - 向量不可用：保留引用图和 metadata，将相似层标记待补算/不可用（设计约定，待浏览器核验）；不得造相似边或把 0 边写成“没有相似”；
  - `title_only`：只记录为该边依据/降级依据；不能声称有独立“标题检索模式”或把它当成所有节点的相似保证；
  - 切层后边被删除：标记为阻塞，保存前后 graph 对照，不继续以视图通过替代持久化验收。

### 步骤 7：拖动、筛选并保存视图

- **操作**：拖动至少一个节点、缩放或平移画布，按年份/下载状态筛选（设计约定，待浏览器核验），点击“保存布局/保存视图”（设计约定，待浏览器核验）。
- **点击后提示**：应出现“已保存”或等价结果（设计约定，待浏览器核验），并保留当前图层开关、筛选与 viewport；隐藏节点不等于移除节点。
- **是否等待**：是；等待 `PATCH /api/literature-maps/{map_id}/view` 返回新的 `revision`。拖动期间不能因每次 pointer move 触发全图重新布局或覆盖别人的更新。
- **等待什么**：记录保存前后 `revision`、`positions`、`viewport`、`filters`、`layers`；确认提交的 node_id 都归属于当前 map，scale 为正且数值合法。
- **下一步**：离开地图视图，执行步骤 9 的保存重开；若只想查看，不点击删除或导入。
- **失败恢复**：收到 `409` 版本冲突时，执行第 5 节的“读取最新 revision → 对照用户改动 → 重新提交”流程；不能覆盖最新布局，也不能静默丢弃用户刚完成的拖动。

### 步骤 8：用户明确触发主动入库

- **操作**：在真实节点详情点击“加入知识库/主动导入”（设计约定，待浏览器核验）；只有用户明确点击才调用 `POST /api/literature-maps/{map_id}/nodes/{node_id}/imports`。
- **点击后提示**：应显示导入已提交、处理中或现有导入句柄（设计约定，待浏览器核验）；查看地图、打开详情、切换图层和重开均不自动下载。
- **是否等待**：是；等待既有安全下载/导入流程返回句柄和最终可观察状态；地图端只做窄 bridge，不另造下载器、登录协议或上传协议。
- **等待什么**：记录 `map_id`、`node_id`、既有导入句柄、`document_id`（若返回）、`download_status`/索引状态以及稳定错误码；确认 external S2 ID 没有被硬塞成 `catalog_paper_id`。
- **下一步**：成功后回到详情确认节点状态更新；用户可稍后从既有知识库流程查看原件和索引状态。
- **失败恢复**：
  - 登录/权限/上传/来源失败：显示既有流程提供的可行动提示与重试入口（设计约定，待浏览器核验），保留节点与地图，不删除 PDF/共享缓存；
  - 不安全 URL 或无法关联：记录固定错误，不能绕过安全校验或另写下载器；
  - 用户未点击导入：保持未导入状态，不能以“查看详情”作为隐式授权。

### 步骤 9：离开后保存并重开

- **操作**：离开当前地图视图（返回地图列表或主导航），再点击刚创建的地图条目（设计约定，待浏览器核验）。
- **点击后提示**：地图条目应显示其主题/名称、项目绑定（如有）、状态和最近更新时间（设计约定，待浏览器核验）。重开后应恢复上次已保存的节点位置、图层开关、筛选和 viewport。
- **是否等待**：是；等待 `GET /api/literature-maps/{map_id}` 与 `GET /api/literature-maps/{map_id}/graph` 返回；这一步只读本地已保存数据，不重新开始发现。
- **等待什么**：记录同一 `map_id`、稳定 `node_id/edge_id`、保存前后 `revision`，以及最新作业状态；确认没有新 `job_id`、隐式下载或关系重算。
- **下一步**：对照步骤 7 的截图/记录，确认视图与详情一致；若作业仍在运行，继续观察原作业，不创建第二张同主题地图。
- **失败恢复**：地图列表中无记录时，先用已记录的 `map_id` 请求详情并记录 `404/503`；不要用另一张地图或旧数据遮盖丢失。位置/开关未恢复时，保留前后 JSON/截图并标记持久化阻塞。

### 步骤 10：结束本次验收并保存证据

- **操作**：确认地图仍可读取，记录最终状态、节点/边计数、partial/失败单元和导入结果；保存脱敏请求响应、页面截图和日志路径（设计约定，待浏览器核验）。
- **点击后提示**：应能看到最终状态 `ready`、`partial`、`stopped` 或 `failed` 之一（设计约定，待浏览器核验）；不把中间 `running` 当作通过。
- **是否等待**：是；若选择验证完整建图，等待作业进入明确终态；若仅验证阶段交付，记录当前中间态并注明未完成原因。
- **等待什么**：等待 job status 与事件游标稳定；记录真实 `map_id/job_id`、最终 `status/step/counts/failed_units` 和产物路径。
- **下一步**：把实际浏览器文案、请求/响应和结果回填到第 7 节模板，再由独立验收角色判断通过/阻塞。
- **失败恢复**：任何关键证据缺失都标记“未完成/阻塞”，不能只凭页面看起来正常就收口，也不能以合成 200 节点图替代真实主题建图。

## 4. `partial` 状态的可操作恢复

`partial` 是可见的部分结果，不是 `ready` 的同义词。最终验收须分别记录“已有成果是否可读”和“缺失单元是否可行动”。所有提示文字仍标记为“设计约定，待浏览器核验”。

| 触发情况 | 用户应看到 | 是否等待 | 用户下一步 | 可操作恢复与禁止事项 |
|---|---|---|---|---|
| 候选不足，实际节点少于 20/30/50 | “仅找到 X 篇，地图以部分结果可用”（设计约定，待浏览器核验），并显示 requested_count 与实际 accepted/node_count | 是，等发现作业进入 `partial` 终态；不等待无期限补满 | 查看已有真实节点和来源，记录 shortage | 保留实际数量；按真实 UI 提供的重试/范围调整动作继续。不得用不相关论文凑满，不得把 partial 写成 ready。 |

## 5. `409` 冲突的可操作恢复

`409` 不等于普通网络失败。先读取响应中的固定 `code/message/retryable`，再按冲突类型恢复；不得盲目重复点击或覆盖服务端最新 revision。

### 5.1 创建幂等冲突

1. **观察**：点击“开始建图”后返回 `409`，记录主题、筛选、limit、幂等 key、响应中的 `map_id/job_id`（若有）和固定错误码。
2. **核对**：使用列表或 map 详情确认同一 key 是否已经创建了同参数地图；不要先创建第二张地图。
3. **恢复**：
   - 同 key、同参数：打开服务端返回或查到的既有地图，继续观察原 job；
   - 同 key、不同参数：保留原请求结果，修正表单后生成新的幂等 key 再提交；
   - 无法确认既有实体：保留 409 证据，按错误提示重试一次；仍冲突则标记阻塞，不能假写 map_id。
4. **通过条件**：同一用户意图最多对应一个可追溯 map/job，且没有重复节点或重复作业。

### 5.2 保存视图的 `expected_revision` 冲突

1. **观察**：拖动/筛选/切层后保存返回 `409`，记录本地待保存改动与服务端 revision。
2. **读取**：重新读取同一地图和 graph，取得最新 positions、viewport、filters、layers、revision；不直接覆盖服务端数据。
3. **比较**：确认他人/另一标签页的新改动；保留用户本次仍想保存的改动作为待提交草稿。
4. **恢复**：在最新 revision 上重新应用必要的节点位置、视图偏好并再次点击保存；若冲突再次发生，停止重复提交并记录阻塞。
5. **通过条件**：保存后 revision 单调增加，位置/图层/筛选与最终页面一致，没有静默丢改动或生成第二张地图。

### 5.3 预算或上限冲突

若接口返回的是节点/预算上限类 `409`，页面应显示当前限制和可行动的下一步（设计约定，待浏览器核验）。Task03 首批数量只能选择 20/30/50；不得把超限提交改写成成功，也不得自动扩展到 200 节点。保留当前地图和已完成成果，等待后续有界扩展任务提供正式预览/确认流程。
