2. frontend-dev：全部短标签及三档切换；min(28,8+2*ln(1+n))半径与描边选中，未知引用不作0；滚轮锚点、工具栏中心、双指中点一致。复用保存视图契约做版本化扩展，默认兼容旧图，不覆盖布局或分组；PNG保持与当前显示模式一致。
3. frontend-dev：显示摘要队列进度、暂停/继续/重试；摘要/全文页签、历史及重新生成。全文状态翻译为用户说明并桥接现有下载/登录/上传/索引恢复，禁止静默自动下载；全文ready才允许调用，服务端继续校验。预填含论文标题/作者/年份的解读Prompt，说明研究问题、方法、结论、局限和证据等级；不发送，不覆盖草稿。

## 核心人工验收案例（开发后以真实ID、按钮与产物补全）

1. 从主导航打开文献地图，新建20篇主题图：地图先出现，所有节点可见作者/年份；未知字段明确回退，节点按总被引数区分尺寸。
2. 无需点分析，观察“完成/总数、排队/失败”；离开重开继续。暂停后当前一篇可完成、后续等待，继续后恢复；重开不重复生成，新增与摘要变化按版本补算。
3. 将鼠标放非中央节点滚轮缩放，锚点不漂移；改变详情面板、页面滚动后复测，手机双指及工具栏缩放分别验证。
4. 打开论文摘要页签，查看自动结果，重新生成时旧版仍可读；失败有明确重试入口，不清空旧版。
5. 全文页签未就绪时按提示获取全文或处理登录/上传/索引；就绪后手动分析，成功切全文页签且摘要历史保留。不得拿标题、摘要或未授权文档冒充全文。
6. 点击关于本篇提问：既有聊天页有可编辑建议草稿与证据标识，无自动发送；已有草稿时不覆盖。全文后来就绪不能改变旧摘要会话范围。

### 最后一批窄修（用户指定导入失败后置）

- 标签屏幕可读下限须包含SVG viewBox与viewport完整缩放，不能仅保持9个SVG单位；以实际CSS像素尺寸定向验证，局部避让不写回节点位置。
- 导入失败诊断见[import-failure-diagnosis.md](import-failure-diagnosis.md)：已保存的真实失败为OA解析阶段S2限流，HTTP202业务失败body已有安全诊断，前端仅显示“失败”导致用户无从恢复。复用现有字段与入口，显示白名单中文原因/可重试性，重开保留；旧记录无诊断明确未记录，成功清除旧错误。此项仅前端投影修复，不重写resolver/下载/PDF安全/身份匹配或引入新上传接口，不自动重试和承诺所有论文必可下载。
- 追加真实根因：一次既有接口重试及官方arXiv只读元数据核验确认，论文ID/标题/年份相同，作者`T.Mei`与`Tao Mei`缩写误拒（3/4=0.75<0.80），S2限流是独立的后续失败。因此除前端投影外，允许对既有arXiv指定ID路径做保守作者缩写兼容修复，保留原阈值、ID/标题/年份及PDF安全门禁；错误首字母/姓氏、歧义和重复匹配必须拒绝，不放宽标题搜索路径。分派backend-dev实现并独立复审后才重新部署/有限真实重试；不是重写下载链或新增来源。
- 同一失败论文经修复后已真实下载并入库（doc `ae3a1c3f7ee746bba031b06306ff3230`），但全文gate暴露canonical来源字段在`KnowledgeBasePaperImportAdapter`重建旧记录时丢失，v1/v2 indexed不等于strict manifest/hash已发布。此必要接缝只允许保留既有canonical字段并复用严格发布路径，不手写hash/manifest或跳过gate；独立复审后通过既有reindex接口一次合法恢复、再真实验证全文。成功入库与全文成功证据分开记录，未完成全文不标READY_FOR_USER。
