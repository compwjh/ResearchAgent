## 1. 分步实施与文件边界

1. **事实与契约冻结**：architect基于已落盘前后端findings冻结接口/迁移；frontend-dev先用用户截图对应真实地图进行只读复现，记录1440/1280/1180/900/390宽度、详情开关、SVG rect/transform、可视节点边界和pageerror。不能把无ResizeObserver当作已证根因。仅在确认后执行复现测试，保留失败证据，不改真实布局。
2. **后端**：backend-dev仅backend与对应测试，实现节点color_override增量迁移、原子节点批量样式、view.node_style及导出。backend-reviewer/tester独立复核，先稳定数据/接口再前端对接。
3. **前端布局/视口**：frontend-dev仅frontend与前端测试，半径感知布局、显式整理预览、真实容器坐标/详情可视性。保留保存位置与用户缩放；不引入D3或另一布局存储。
4. **前端配色**：统一调色板、单/多选/分组改色、颜色覆盖/跟随、地图级填充模式、最近色及导出外观。选中不强行实心填色。
5. **前端状态反馈**：摘要分析/全文分析页签，中文入库/索引状态和邻近醒目说明卡片；移除常驻学术立场文案。保持原文入口与分析入口区分。
6. **验收与收口**：单端独立review/test；真实API与浏览器成功链、最终全量、tester与architect签字、实际部署、复盘及状态同步。Git由主会话统筹，不自动push/合main。

## 2. 布局/视口实施约束

- 自动布局对所有未移除节点（包括暂时被筛选隐藏的节点）约束：圆间净空>=2×较大直径。以citationRadius为几何基线并额外预留描边安全量；不改变引用数对数半径公式。
- 使用有界确定性布局/分离；有限迭代未满足时使用确定性无碰撞布置兜底，不能无限迭代或报告“基本满足”。允许扩大图面，不强迫200点全部塞进小画布；密集图通过缩放/平移浏览，沿用可读性保护。
- 新建图自动布局；旧图只检测并提示整理。旧图扩展仅给新点找空位，不搬旧点；旧点互相违规时仍提示显式整理。
- “整理间距”预览不写后端，暂停可能把预览位置写回的旧自动保存/拖动持久化路径；确认按现有revision保存全部未移除节点位置，取消还原全部位置/视图。人工拖动不推其他点，筛选不重排；本轮不做布局历史库或多级撤销。
- 点开详情不改变节点位置或自动全图fit，保留缩放；选中点因面板变化不可见时只做最小必要平移。关闭面板不强制重置视角。容器尺寸稳定后重算坐标，不在0尺寸时保存错误viewport。
- 标签保留现有显示模式，布局不因临时多选或着色重算；本轮圆间距是硬约束，不承诺200个完整标签在任何缩放下同时无重叠。

## 3. 配色实施约束

- 一个节点仍只有一个group_id，多选使用前端Set，不引入节点多组关系表。有效色=节点color_override→分组color→默认紫色。切换/删除分组不清除节点独立色；“恢复跟随分组”写null。
- 单点右侧节点外观、多选工具栏、分组色块共用调色板。12个多巴胺预设、自定义HEX、最近8色；不做框选。多选模式下点击增删，显式退出回到单点详情；仅当前可见未移除节点可选，切图清空，筛选隐藏的选择项移除并更新N。
- 点色本地预览；“应用到N篇”才提交。取消复原；失败不更新正式颜色、保留选择/色稿并给中文原因。409须重新读取核对后显式重试，不静默覆盖。批量最多200个唯一节点，事务全成/全不改；提交期间防重复，应用请求发出后不把取消/离开页面冒充撤销；网络中断显示保存结果待确认，通过GET核验，不谎称全部未改。
- 最近色仅在成功应用后更新、六位HEX规范化去重、最近使用排前；浏览器localStorage按当前owner分隔、跨地图复用。存储不可用时仅当次会话保留，不阻断地图保存。
- 地图级node_style：filled默认、fill_opacity=0.3；outline内部透明；描边始终不透明，颜色/透明度不影响标签。选中用描边/细环，不把原色改成实心高亮。
- PNG渲染与已应用样式一致；JSON保留override、group及地图样式，不包含最近色、临时选择或未确认预览。

## 4. 全文/中文反馈

- 页签“摘要分析／全文分析”展示分析结果和状态，不是PDF阅读器；原文继续走既有“打开原文”。
- 点击全文分析立即出现同一邻近卡片：未入库→获取并加入知识库；登录/失败→既有恢复；已入库未索引→等待/修复；全文ready尚无结果→开始全文分析；分析中→进度；完成→当前结果与历史。
- 分别读取导入状态与source_status；根据实际阻塞原因区分等待索引、索引失败/来源版本不符需修复、权限范围不满足，不能对所有indexed但未ready节点统一让用户无限等待；indexed/存在document_id不能冒充全文ready。全字段统一中文标签，不把未知机器码直接展示；未知给“状态待确认”，已入库不翻译为“全文分析完成”。
- 不可用仍可点击获原因，但不发无依据analysis请求；恢复必须用户触发，不自动下载/登录/上传/全文分析。
- 移除“颜色只表示人工整理，不表示学术立场”及同义重复说明，包括常驻文本和保存成功后的附加句；保存只提示颜色已保存，保留数据来源/证据等级等必要信息。

## 5. 核心人工验收案例（开发后补真实ID与逐步最终提示）

1. 打开已有20篇、大小不一节点的地图。旧位置保持，若间距不足显示“整理间距”；点开预览，取消后不变，再确认保存；等待明确保存结果，重开后位置仍在。新建图另验自动满足相同净空。
2. 点某节点，详情出现且地图不空白，原缩放保持、该点可见；关闭、切换点、跨桌面断点及手机抽屉重复。失败保留当前图并给可恢复提示，不要求用户手动删布局。
3. 在单点节点外观选预设色，先预览，取消不变，再应用并等待保存提示；打开多选点两个节点，显示已选2篇，应用同色；刷新后仍在，未选节点与group_id不变。
4. 给某点独立黄色，再把分组改绿色：该点仍黄、其他跟随点变绿；恢复跟随分组后该点变绿。自定义色成功后出现在最近8色，重开浏览器可复用；取消预览不进入最近色。
5. 填充默认30%，改仅描边/其他强度并应用；刷新与PNG/JSON保持已保存效果，选中不再变成不透明实心点。
6. 打开全文分析，未入库、未索引和ready分别有醒目中文状态及下一步。准备一篇真实可用全文，用户点击开始全文分析并等待进度/结果，不能只证明未ready提示。入库状态各分支均中文。
7. 两页面对同图产生revision冲突，旧页批量应用不能部分改色；提示重新读取核对，选色稿保留，人工确认后重试成功。

API E2E须从已部署服务真实创建/读取地图开始，经批量改色→地图样式→重读→冲突失败→重新核对保存→JSON导出核对；保留真实源论文、实体ID、HTTP与文件产物。原始失败证据不覆盖，不用mock取代成功链。浏览器另证明PNG实际颜色/透明度、真实详情空白复现关闭、可见净空、单/多选/整组交互。
