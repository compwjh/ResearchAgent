# Task 06：旧文档补建、韧性与性能

> 关联：[Spec 018](../../specs/018-knowledge-document-chunk-inspector.md) ｜ [任务索引](./README.md)
> 依赖：Task 04、05；被依赖：Task 07；当前状态：`待执行`

## 一句话目标

证明旧 PDF 可通过 Task02A 的恢复式自动重建安全获得检查器能力，并补齐中断、恢复失败、损坏、大文档和窄屏场景。

## 当前证据

- 本机已有多份 v1/v2 PDF 数据，但不能把用户原文提交为测试 fixture。
- 新文档清单是派生缓存；旧索引缺 provenance 时必须通过 Task02A 的恢复式重建升级，不能旁路伪造 anchors。

## 前置门禁

- Task 04/05 各自评审通过。
- 真实用户数据测试只记录计数、hash 和状态，不落盘原文片段。

## 执行阶段

1. 对脱敏旧格式 fixture 执行迁移与首次自动升级，只重建已有可用版本。
2. 验证删除前预计算、完整 point/vector 快照、短写入窗口、成功校验和快照删除。
3. 模拟 v2 模型失败、embedding 失败、写入失败、验证失败、服务重启和恢复失败；全部恢复旧索引。
4. 验证首次自动失败后刷新不重试，用户手动操作才能再次提交；并发打开只领取一个任务。
5. 用接近上传上限的大文档验证页面懒加载、切片分段渲染和内存上限。
6. 以真实浏览器验证桌面双栏、窄屏切换、键盘、双向滚动和 hostile 零外部网络请求。

## 子 Agent 分派

- backend-tester 负责后端韧性；frontend-tester 负责静态/交互契约；tester 汇总跨端。
- 测试不修改业务代码；发现缺陷分别回退 Task 04 或 05 由对应 dev 修复。

### 固定 Prompt

```text
你是 Spec018 的跨端 tester。先读 Spec018、Task02A/02B、Task06、Task04/05 执行结果和单端报告。用脱敏 fixture 验证旧 PDF 首次自动重建已有版本、完整 point/payload/dense+sparse vector 快照、预计算后短写入、全部故障恢复、成功删快照、并发单任务、首次失败后仅手动重试和 partial 切换；不得修改真实用户索引。真实浏览器验证桌面/窄屏联动以及 hostile PDF/Markdown 除同源 source/worker/API 外零网络请求。报告不得包含原文或绝对私人路径。
```

## 主 Agent 校验

- 报告中没有用户文档内容。
- 每个缺陷都有对应端修复、复评和复测闭环。
- 性能结论包含样本规模、浏览器、峰值内存/渲染时间，不写“感觉流畅”。

## 测试与验收

- 旧文档、恢复、安全、性能与响应式全部达到 Spec 验收标准。

## 风险、停止与回滚

- 任何测试修改用户原件或向量立即停止；不得以 reset/clean 回滚。

## 产出物

- 单端报告、跨端韧性与性能报告、缺陷闭环证据。
