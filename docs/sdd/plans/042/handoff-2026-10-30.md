## 建议优先完善的事项

1. **CLI 失败退出码**：`eval_run.main()` 和薄封装 `main()` 最后返回 0，而 run summary 可记录 write_errors。验收报告称“退出码反映写回失败”，该结论需要用失败注入测试核实并修正实现或文档。
2. **完成状态与门禁**：现有 Spec 标记“已完成/有条件通过”，但需求/技术评审仍写“待评审（未执行）”，历史全量也存在失败和排除项。不得直接把本次 checkpoint 当作满足所有 SDD 收口门禁，应复核并纠正状态与台账。
3. **重复 score 实际收敛**：历史删除异步队列未证明每个目标 trace 恰余一条。先只读检查当前 Langfuse 状态，再决定是否继续清理；清理会实际删除 score，必须严格限定 task、目标 trace 与待删 ID，保留非目标数据。
4. **本地幂等状态可靠性**：核对状态与服务端是否失配、判官/配置变化是否应触发重新写回，以及中途中断和并发运行时的恢复语义。目前状态在整轮结束后保存，需验证失败窗口。
5. **memory 人工一致率**：现有 gold 为构造真值，不能当作独立人工标注。补充真实、带 prior_context 的样本和人工标注后再评估。
6. **评测计数口径**：judge_calls 当前统计调用过判官的样本数，不一定等于 repeats 展开的实际模型请求数，应明确字段语义。
7. **产物管理**：交接中保留历史 JSON、NDJSON、score 状态及清理备份供复查；后续决定哪些是长期 fixture、哪些应迁移成运行产物，避免直接把旧 score 状态用于新环境。
