# Task 09：桌面项目树与会话菜单重构

> 关联：[Spec 022](../../specs/022-project-conversation-memory.md) ｜ 索引：[README](./README.md)
> 依赖：Task05、Task09 范围确认；被依赖：Task06、Task08；当前状态：`已完成`

## 一句话目标

把桌面侧栏改造成清晰的“项目 → 会话”树，并用不被裁剪的悬浮菜单和项目内弹窗完成创建、移动、重命名、归档及删除。

## 当前证据

- 旧 `.project-switcher` 和新 `.flat-projects` 同时存在，形成两个灰色“项目”标题。
- 旧 `new-project-form` 虽设置 `hidden`，但作者 CSS 的 `display: grid` 覆盖隐藏效果，创建项目表单常驻侧栏。
- 项目标题直接显示“最近更新”和“归档项目”，没有收进约定的 `⋯` 菜单。
- 会话菜单位于带滚动裁剪的列表中，弹层会被相邻区域遮挡。
- 会话移动仍使用浏览器原生输入框要求用户手输准确项目名称，既不美观也容易输错。
- 项目与会话目前是两个平级列表；绑定后会话没有移动到对应项目下方。
- 用户提供的前两张截图只用于证明当前错误；第三张 ChatGPT 截图是信息层级与交互参考，不要求逐像素复制。

## 冻结交互契约

### 侧栏信息架构

- 只保留一个“项目”标题；标题左侧箭头折叠或展开整个项目区域。
- 标题右侧依次为 `⋯`、`＋`，仅在标题 hover 或 `focus-within` 时出现。
- `⋯` 包含“最近更新”“名称 A–Z”“查看归档项目”；`＋` 只打开新建项目弹窗。
- 项目使用“箭头 + 文件夹 + 名称 + 行级 `⋯`”结构；一次只展开一个项目。
- 点击箭头只控制展开，点击项目名称设置项目上下文；不得自动移动当前已打开会话。
- 项目下缩进显示绑定会话，按最近活动时间倒序；每次加载 10 条并支持“查看更多”。
- 项目内会话只显示单行标题，当前会话高亮；行级 `⋯` 仅在该行 hover/focus 时出现。
- 未绑定会话单独放在“最近会话”，每次加载 20 条并继续滚动加载；不再显示重复的“未绑定项目”徽章。
- “最近会话”标题提供 hover/focus `⋯`，其中包含“查看归档会话”。
- 空项目展开后只显示轻量的“＋ 在此项目中新建对话”入口。

### 创建、移动与项目上下文

- 创建项目使用居中的项目内弹窗，只要求名称；删除旧常驻表单及其兼容事件绑定。
- 创建成功后关闭弹窗、选中并展开新项目，进入未持久化的项目会话草稿；第一条有效消息时才创建会话。
- 会话“移动到项目”使用可搜索的已有项目选择框，只列未归档项目、按名称排序、排除当前项目；用户不能创建或输入不存在的项目。
- 移动弹窗包含“让绑定前的历史消息也参与项目记忆”复选项，默认关闭。
- 移动成功后保持当前聊天打开，目标项目自动展开，会话从“最近会话”或旧项目立即移入目标项目并保持高亮。
- 取消或移动失败不得污染当前项目、展开状态、列表或会话绑定。
- “移出项目”保留为会话行菜单中的独立操作。
- 顶部新建对话和“对话”主导航继续遵循 Spec022 已冻结的惰性草稿与项目上下文规则。

### 菜单、弹窗与归档

- 项目行菜单：重命名、归档、删除；会话行菜单：重命名、移动到项目、移出项目、归档、删除。
- 新建、移动、重命名使用项目内对话框；归档、删除使用项目内确认框；不再使用浏览器原生 `prompt/confirm`。
- 菜单浮层脱离滚动裁剪上下文；靠近底部时向上展开，同一时间只打开一个。
- 点击外部或按 Esc 关闭菜单，焦点返回触发按钮；键盘和鼠标行为一致。
- 归档项目与归档会话使用独立列表状态，不混入普通列表；归档项只提供恢复和删除，返回后恢复此前项目展开状态和滚动位置。
- 视觉沿用 ResearchAgent 的颜色、字体与组件体系；ChatGPT 截图只约束层级、收起/展开和菜单位置。

## 数据与接口增量

- 不新增表，不改变项目、会话、记忆、RAG 或文档关联领域语义。
- `GET /api/projects` 的项目对象增加只读计算字段 `last_activity_at`：取项目自身 `updated_at` 与其未删除会话最新 `updated_at` 的较新值。
- API 默认项目页按 `last_activity_at DESC, project_id DESC` 排序；项目 cursor 同时编码这两个键，并按相同键集继续分页，禁止以旧 `updated_at` cursor 混用新排序。
- “最近更新”直接使用 API 的一致排序；“名称 A–Z”仅在当前完整已加载项目集合中浏览器本地排序并保存偏好。
- 继续复用 `GET /api/conversations` 加载项目子会话和归档视图，不建立第二套会话存储或移动接口；增加可选筛选 `status=active|archived` 与 `unbound_only=true`：未绑定主列表请求 `status=active&unbound_only=true`，全局归档会话请求 `status=archived`，项目子树请求 `project_id=...&status=active`。
- 继续复用 `PATCH /api/conversations/{id}` 完成移动与历史策略确认。

## 子 Agent 分派

1. backend-dev：只增加 `last_activity_at` 的 repository/API 计算与定向测试，不改变持久化 schema。
2. frontend-dev：删除遗留侧栏 DOM 与事件，实现项目树、嵌套分页、浮层菜单和统一弹窗。

每个子 Agent 必须返回：结果状态与摘要、改动文件、测试命令/退出码/结果、产物路径、决策依据、风险与阻塞、主 Agent 后续动作、开始/结束/总耗时；可用时补模型、token 和工具统计。

## 定向测试与验收

- 页面只有一个“项目”标题，旧项目下拉和常驻创建表单不存在。
- 无 hover/focus 时标题和行级操作均隐藏；出现后为 `⋯ / ＋` 图标而非文字按钮。
- 项目手风琴、整体折叠、空项目入口、10 条子会话分页和未绑定会话滚动加载正确。
- 绑定会话后 DOM 立即从未绑定区或旧项目移动到目标项目下，不重复、不刷新聊天、不丢消息。
- 移动弹窗只能选择已有未归档项目；取消、失败和历史策略选择均符合冻结契约。
- 菜单在侧栏底部和滚动容器边缘不被裁剪；外部点击、Esc、焦点返回和键盘操作通过。
- 项目/会话归档视图、恢复、删除、返回状态和项目最近活动排序通过。
- 用户提供的错误截图场景逐项复现为已修复；使用第三张截图的信息层级完成真实浏览器对照。
- `node --check`、前端契约测试、必要的后端精确测试与 `git diff --check` 通过。
- Task 收口部署到本地服务供用户验证；本 Task 不运行全量回归。

## 风险、停止条件与回滚

- 任何会话错误归属、跨项目记忆污染、移动取消后状态改变或菜单不可键盘访问均阻塞验收。
- 不以复制第二套项目/会话状态解决嵌套展示；树与聊天必须消费同一 `conversationState` 和服务端身份。
- 若计算最近活动时间导致项目列表显著退化，先优化单条聚合查询；不得改为前端为每个项目加载全部会话。
- 项目排序或 cursor 发生重复、遗漏或跨页错序即停止验收；不得以旧 `updated_at` cursor 包装 `last_activity_at` 结果。
- 已绑定项目的归档会话必须可从全局“归档会话”恢复或删除；不得因树过滤而成为不可治理记录。
- 回滚只撤销本 Task 的 UI/API 增量，恢复 Task05 已提交基线；不 reset、stash、clean 或覆盖用户修改。
