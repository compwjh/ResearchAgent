## 五、发现的问题与严重级别

- **非阻塞（强制约束）— F1：task-05 / task-07 依赖边缺失（P1 级计划缺陷）**
  - 现象：`task-05-contract-tests-and-e2e.md` 头部声明「依赖：任务 04」，但其验收第 5/7 条明确覆盖 C 域（C-1~C-12、公式浮层复制、窄屏点按）。而 `task-07-answer-math-rendering.md` 声明「依赖：任务 01」、`README` 依赖链把 `07` 画成从 `04` 分出、与 `05` 平行、不回灌 `05`。
  - 后果：严格按声明依赖边调度会先于 task-07 执行 task-05，使 C 域契约/E2E 无实现可验（C 域实现尚未落地）。
  - spec 文本已写「07 逻辑位置在 04 与 05 之间」，意图清晰，仅缺失形式化依赖边 `07 → 05`（或显式执行顺序约束「07 须在 05 之前完成」）。
  - 级别：P1（执行时序错误风险），非阻塞（意图明确、修正为一行依赖声明）。
- **跨评交叉 — P1：脱敏函数深度上限与 source_ref 嵌套不兼容**
  - 该项为技术/数据契约缺陷，已在 `044-tech-review.md` 以「打回」结论详述（source_ref 字段处于脱敏 depth 4 被整键丢弃）。需求评审侧仅作交叉提示：spec「数据模型 / 明确不做」与决策基线 D8「嵌套深度沿用既有上限（深度 3）」「复用 `_sanitize_processing_detail_json()`」的「兼容」表述不成立，须随技术评审修订一并修正，否则 A 域来源动作路由无数据可用。
