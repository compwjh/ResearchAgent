## 一、目标清晰性 —— PASS

- 「一句话目标」（`:10`）同时给出**做什么**（上传 PDF → 解析/切片/向量化 → 混合检索 → 带引用流式回答）、**做成什么样算对**（全本机、无外部 API、引用带页码）、**技术边界**（bge-m3 稠密 + jieba/BM25 稀疏 + RRF 融合、Qdrant 本地模式、reranker 可插拔）。
- 关键取舍均已写清理由，不是隐含假设：为什么不用 FAISS（payload 过滤缺失）、为什么稀疏侧自算（Ollama 实测不返回 sparse）、为什么 `num_batch=1024`（上下两个边界，下界会造成**静默劣化**，`:17-20`）。
- 与既有模块的边界明确：「不改动 `/api/chat`、`/api/agent/*`」（`:49`），并复用顶部 `modelSelect`（`:26`），避免第二套模型选择实现（对齐 `regression-guard` 项目增补第 9 条「禁止重复实现」）。

判定：目标无歧义、可验证，**PASS**。

## 二、范围可测 —— PASS

- 端点表（`:50-56`）给出「动作 / 输入 / 成功返回 / 失败状态码」，每个端点都有可断言的返回结构。
- 数据模型（`:30-39`）字段带约束，`status` 枚举取值明确（`indexing/indexed/failed`，另在边界中补 `indexed_partial`），可写成断言。
- 边界章节（`:70-85`）标题即声明「每条可写成测试」，11 条边界 + 3 条前端安全/性能边界均可落到用例；验收报告 `011-acceptance-review.md` V13–V19、V21 已逐条以单测/实测对应，构成**可测性已被实践验证**的闭环。
- 混合检索流程（`:58-63`）给出参数（top-N=30、RRF k=60、top-K=8/5），非模糊描述。

判定：范围可测，**PASS**。

## 三、边界与「明确不做」完整性 —— PASS

- 「明确不做」（`:97-104`）共 7 条，覆盖：云端能力、其他向量服务、LangGraph 查询改写、reranker 强制依赖、语法高亮/编辑器/导出、异步索引与进度条、聊天窗口 Markdown（后改）。
- 两处**变更留了痕而非悄悄删改**：`"点击引用查看原文片段"` 与 `"普通聊天窗口不渲染 Markdown"` 均以删除线 + 日期 + 原因标注为「用户要求后已改变」，并说明原裁决作废（`:102`、`:104`）。**范围变更可追溯**，非事后扩范围。
- 缺陷补充（`:87-95`）按「同功能范围不新建编号」处理 Markdown 渲染缺陷，并追加 P17–P20 验收点；这是范围**澄清**（原状态「回答呈现不完整」），不是新功能，判定合理。
- 与「明确不做」自洽性核对：`不做异步索引与进度条` 与产品步骤 2「无持续『索引中』态」一致（`:115`）；`reranker 非必须` 与验收 V21「缺失降级」一致。

判定：边界闭合、范围划死，**PASS**。
