## 结论：打回（BLOCK）

已授权的产品范围清晰：修订沿 Spec 030、真实报告至少覆盖 5 篇论文、摘要级证据可用但必须标明限制、正文至少 1,500 个 CJK 表意字符、至少 1 项跨论文比较及 3 条有证据支持的综合发现；证据不足须显式部分完成，不得由目录 fallback 冒充正式报告。范围与明确不做项也足以避免重开 Spec 042 或重跑历史任务（Spec030 修订第 110–152 行；Grilling 第 50–54 行）。运行审计把两个样本明确限制为抽样，且未把 fallback 认定为特定报告根因，这一证据边界合适（runtime audit 第 9–11、30–46 行）。

阻塞在“实质内容”验收仍不可复现：CJK 计数、结构项数量和 Evidence ID 关系是可机械核验的结构门槛；合同同时要求不重复凑字、逐篇分析有实质、比较确实比较、结论符合其证据等级，但 Task10 没有规定谁按什么可观察标准判定这些语义要求通过。仅检查字段存在、字数与引用有效，仍可能让重复或空泛文本通过；不能把结构校验称为语义质量校验（质量合同第 9–12、16–20、62–64 行；Task08 第 19–21 行；Task10 第 12、20、26–28 行）。

## 解除条件

1. 在 Task10 加入独立内容评审的 PASS/FAIL rubric，并要求对真实 API E2E 的最终产物留存逐项证据。至少分别核实：每篇方法/发现/局限与所用来源相符；跨论文比较实际覆盖已批准维度且引用所涉论文；每条综合发现由至少两篇论文的有效证据支持；摘要证据没有被扩写成全文实验细节；缺失信息明确标未知。无法由确定性代码证明的项目应标为人工语义评审，不应假称自动质量保证。
2. 将“重复文本不算实质分析”落实为该验收 rubric 的拒绝条件及可复核例子，不必另造模型评分系统。
3. 修订后重做本需求评审；无需再次请求用户确认已经授权的产品范围。
