## 当前复现的真实代码缺陷

### P1 — Playwright 版本门禁与依赖不一致

- `requirements.txt:9` 与 `requirements.lock.txt:48` 固定/约束 `playwright 1.62.0`。
- `backend/app/services/paper_browser_manager.py:45` 仍是 `PINNED_PLAYWRIGHT_VERSION = "1.52.0"`。
- 当前实测：`.venv` 中 Playwright 版本为 `1.62.0`，`PaperBrowserManager(...).health()` 返回：

  ```text
  {'available': False, 'version': '1.62.0', 'supported_sites': ['acm', 'ieee'], 'reason': 'BROWSER_UNAVAILABLE'}
  ```

这会让浏览器健康接口报告不可用，即使 Python 依赖已安装；需由 junior-dev 修正版本契约并补真实版本一致性测试，随后再判断浏览器二进制/OS 权限。

### P1 — 默认公开下载 allowlist 为空，路由公开导入必然被拒绝

- `backend/app/core/article_settings.py:41` 的 `paper_discovery_allowed_hosts` 默认是空列表，`article_download_urls` 当前也为空。
- `backend/app/api/routes.py:435-451` 的 `_paper_candidate_hosts()` 在默认配置下实测返回 `set()`。
- 用合法 HTTPS、公开站点形态的候选调用生产下载器，实测立即返回 `DOWNLOAD_BLOCKED / 下载地址被安全策略拒绝`，尚未发出请求。

这不是公网波动，而是默认配置与“公开 PDF 可导入”目标不一致。下一任务需明确固定服务器 allowlist 的默认来源（或要求部署配置并在启动时 fail-fast），并补路由级公开 PDF 回归；不能把 Task05 的直接服务 fake 测试当作 API 闭环。

### P2 — Playwright 专属 TimeoutError 被误映射为 BROWSER_CRASHED

`backend/app/services/paper_browser_manager.py:149-154` 只捕获 Python 内置 `TimeoutError`。Playwright 的 `playwright.sync_api.TimeoutError` 不属于该类（当前实测 `issubclass(...)` 为 `False`），因此页面超时会进入通用异常分支并返回 `BROWSER_CRASHED`，而不是 Spec015 规定的稳定 `BROWSER_TIMEOUT`。

最小 fake 复现：让 `page.goto()` 抛出 Playwright `TimeoutError`，当前结果为 `code=BROWSER_CRASHED`。需由 junior-dev 补 Playwright TimeoutError 映射及测试。

### P2 — 认证 PDF 路径未执行页可读性/加密校验

`backend/app/services/paper_browser_manager.py:257-275` 只检查响应头、大小和 `%PDF-` magic；它没有复用 `paper_download._validate_pages()`。当前 fake 认证响应 `content-type=application/pdf`、body=`%PDF-not-readable` 会直接返回成功的 `DownloadResult`，而不是 `INVALID_PDF`。这使认证链路的错误码和“非 PDF/不可读取 PDF 不得进入知识库”契约不一致，需补页数/加密校验与失败清理回归。

### P2 — 论文入口仍有 feature flag 首屏闪现风险

`frontend/index.html:19` 的论文导航初始未隐藏；`frontend/app.js:351-357` 在没有注入值时默认 `true`，而 `frontend/app.js:96-112` 才在异步 `/api/health` 返回后应用服务端开关。若服务端关闭功能，首屏到 health 返回前仍会显示入口，违反“关闭时入口不出现”的严格语义。需要静态注入开关或服务端渲染隐藏状态，并补真实/行为测试。
