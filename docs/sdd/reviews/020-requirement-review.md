# 020 需求评审

> 结论：**通过**（由主 agent 代行需求评审，非独立角色评审）
> 评审对象：[spec-020 零碎 bug 解决](../specs/020-misc-bug-fixes.md)

## 需求来源与可核验性

本 spec 定位为"零碎 bug 容器"，承接两类用户实际反馈：① 点击批量导入无即时反馈、显示"正在提交 0 个导入批次"；② 导入论文在知识库 v2 恒为"待索引"。两条现象均已转写为可测试边界（即时反馈不依赖二次点击、计数 N≥1、卡片动画、v2 状态由 pending 真实流转）。

## 范围与划界

- 两类 bug 修复均**不引入新功能**：BUG-01 仅改反馈时机与计数口径，BUG-02 仅让导入对齐上传（补 v2 异步提交）。
- 明确不做：不改 v1 索引逻辑、spec-012 双版本检索语义、上传路径、CAS/并发/租约、下载安全策略、前端接口契约与 DOM id。范围划死，符合"零碎 bug"定位。

## 结论

两条问题根因清晰、修复方案与既有上传路径一致、验收点可执行 → **通过**，可进入技术评审与实施。

## 遗留（不阻塞）

需求层面无 P0/P1。建议后续把"导入前先校验候选是否可解析"（避免 424 `KB_IMPORT_FAILED` 这类论文自身问题打扰用户）纳入新一批，但属增强项。
