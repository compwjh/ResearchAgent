## 四、强制约束清单（Q-1 ~ Q-6，dev 必须逐条落实并在回执中逐条引用）

- **Q-1（文档一致性，阻塞验收）**：把 A 段标题 `:1883` 的「（待确认）」与 C 段标题 `:1986` 的「（范围扩大，待确认）」改为「（已确认，实施中）」，与状态行一致。**本约束由 architect 在合并前落实**，dev 不必改 spec。
- **Q-2（文案一致性，阻塞验收）**：重命名 409 必须向用户显示 spec `:2025` 指定的「地图已在别处更新，请刷新后重试」，**不得直接透传**后端现文案（`routes_literature_maps.py:326`「地图版本或作业状态已变化，请重新读取后重试」）。理由：spec 边界 2 是验收口径，且后端该文案面向 `/view` 保存，语意不适合重命名。
- **Q-3（失败恢复，阻塞验收）**：新增两条产品步骤并实测：①删除时后端返回 404/503 → 列表不变、状态区有可读中文提示、菜单仍可再次触发；②删除确认后列表重取失败 → 给出「本地已移除但刷新失败，请点刷新」类提示，不得静默。
- **Q-4（版本号文件清单，阻塞验收）**：`css?v=30→31` / `js?v=44→45` 必须同步 **7 个测试文件**（见 R12）+ 生产页 2 处 + fixture 2 处，且 `test_frontend_map_header_actions_readability.py` 的 `MAP_JS_VERSION`/`MAP_CSS_VERSION` 常量要一并核对（grep 仅 5 处命中，须逐文件读实际写法）。
- **Q-5（空名称拦截，阻塞验收）**：重命名提交前必须 `trim()` 后判空/超 200 字符并在前端拦下，**不得提交**；依据 `store.py:657` 后端不会拒绝空串。
- **Q-6（范围守门，阻塞验收）**：一级列表**恰好 3 项**且不含导出；不得顺手把 `导出 JSON/PNG`（`literature-maps.js:1164,1169`）搬进列表；不得新增端点/表/字段/`schema_version`；不做撤销/回收站。任何超出须停下改 spec 重新请求确认。

## 五、风险与建议（非阻塞，建议在验收记录中登记）

1. **「不可恢复」表述与软删事实**：后端是软删（`store.py:714`），文案称「不可恢复」是**面向产品能力**（无恢复端点）的诚实描述，但数据实体仍留在库中。建议验收记录写清「无恢复入口，等同不可恢复」，避免日后被当作功能缺陷。
2. **删除当前选中地图的自动切图**：冻结为「切到列表第一张」，则「第一张」的定义依赖 `list_maps` 的排序（`store.py:596` `ORDER BY updated_at DESC, map_id DESC`）与前端 `filteredMaps()` 的交集；建议验收时明确「第一张 = 当前筛选后列表首项」，与 `state.maps` 顺序一致即可。
3. **760px `⋯` 22→44px**：属体验改进但会挤压卡片右上徽标区（`:491` `padding-right:30px` 需同步放大到 ≥50px），建议在需求产物里附 760px 截图对比，避免只看按钮尺寸而漏看徽标重叠。
4. **spec 巨型文件**：本 spec 已 2085 行、含多个日期批次，建议本批次收口时把「待确认」类历史段落归档到 `docs/sdd/specs/043-archive/`（不属本批次范围，仅建议）。
