## 评审意见

### 1. 目标清晰且可被用户理解

通过。目标明确描述了独立“论文检索”Tab、面向安全顶会或用户配置会议、按研究方向进行语义相关性排序，以及单篇/批量下载并导入知识库。用户最终获得的是“可检索、可判断、可入库”的完整结果，而不是只得到外部搜索链接。

目标与范围一致：DBLP 负责主会召回，OpenAlex 做补全，spec-014 提供重排，既有知识库负责最终导入；明确不做项排除了 Google Scholar、补充材料、引用网络、云端服务和绕过访问控制等扩张方向。

### 2. 用户旅程完整、可操作

通过。当前 8 步产品旅程形成以下闭环：

1. 打开入口并输入研究方向，确认默认会议和年份后搜索。
2. 查看标题、作者、年份、会议、摘要状态、相关度和 PDF 状态，并调整条件重搜。
3. 在会议设置中搜索 DBLP 会议并保存自定义来源。
4. 单篇导入时观察下载、校验、索引进度。
5. 批量导入时区分成功、失败和等待登录的条目，公开项不被登录项阻塞。
6. 在受控浏览器中由用户完成 ACM/IEEE 登录，再续传原任务。
7. 已入库论文显示已有状态，重复操作不生成副本。
8. 对无 PDF、无权限、无效 PDF 和服务降级显示原因及可执行的重试/登录动作。

实现约束：前端只能使用服务端返回的 `search_id`/`candidate_id`；不能自行拼接或展示未经服务端确认的下载 URL。异步批次在用户离开 Tab 后仍需提供可查询进度，返回 Tab 时应能恢复当前批次视图。

### 4. 边界、失败体验和恢复路径

通过。Spec 的边界覆盖了用户可感知的主要失败路径：空查询/无会议/非法年份、单源失败、空结果、过期搜索会话、伪造候选、重复导入、公开下载失败、等待登录、浏览器不可用、服务重启、索引失败和旧记录兼容。产品侧应保持以下结果语义：

- 单源降级不是整体失败，必须在搜索结果区域给出可理解的“部分来源不可用”提示。
- Reranker 不可用时仍显示初排结果，不能伪造精排分数或让用户误以为排序质量不变。
- 批量任务以条目状态为准；批次总体状态应能表达部分成功、等待登录和失败，不能只显示一个模糊的“处理中”。
- 下载成功不等于导入成功；只有知识库索引真实完成才显示成功。
- 登录失败、取消或浏览器崩溃应留下可重试状态；用户不需要重新搜索已过期或已完成的其他条目。
- 安全拒绝应显示稳定错误类别和可执行动作，不展示 Cookie、Authorization、完整查询参数或敏感 URL。

### 5. 产品范围和交互约束

通过。以下范围边界清晰且应保持不变：

- 只支持配置的安全会议和经验证的 DBLP stream，不把本功能扩展成全网学术搜索。
- 只导入论文 PDF，不下载补充材料、数据集、代码或视频。
- 只允许用户在真实浏览器中完成合法登录，不收集、上传或记录密码、Cookie、profile 内容。
- 复用现有知识库导入能力和 spec-014 reranker，不新增第二套索引、云端向量库或另一个重排系统。
- 不自动删除已导入论文，不改变既有聊天页文章下载流程。

### 产品实现前约束（不改变结论）

1. 在任务 02 完成 Go/No-Go 之前，不向用户展示“已支持 ACM/IEEE 导入”的成功承诺；没有合法账户时 A10/A11 必须保持真实阻塞。
2. UI 的排序状态需同时区分 `final_score`、初排降级和“摘要缺失”等可影响判断的状态，避免把技术分数包装成绝对质量承诺。
3. 批量导入进度至少按条目显示状态、稳定错误码/说明和重试动作；总体进度由条目真实状态聚合。
4. 会议设置必须让用户看出内置来源与自定义来源的差别，以及停用对默认搜索范围的影响。
5. A14 的冻结标注集应在首次查看最终排名前落盘，并在验收页面/报告中注明评估样本版本；不能为通过验收临时更换样本。
