# 评审文档目录

本目录保存每份 spec 的评审记录，全部落盘。

> 逐道门禁的可勾选清单见 `docs/sdd/SDD-GATE-CHECKLIST.md`；硬规则见 `AGENTS.md`「门禁执行硬规则」。
> **每份评审文档必须在头部写明四要素**（用于事后审计"是谁评的"）：
> `评审者`（tech-lead 子代理 / 主模型）、`角色`、`模型`、`分派方式`（`Task(subagent)` / 主模型代行+原因）。
> **结论必填**：只能是通过/打回（验收为通过/不通过）；**禁止**留「/」占位。

- `NNN-requirement-review.md`：需求评审（开发主管），确认目标清晰、范围可测、边界与"明确不做"完整、产品使用步骤可操作。
- `NNN-tech-review.md`：技术评审（开发主管），确认数据模型、接口、模块拆分、模型与上下文预算合理。
- `NNN-acceptance-review.md`：验收评审（测试出报告 + 开发主管签字），实现完成后按 spec 的"产品使用步骤/验收场景"执行验收，结论通过/不通过。

评审结论为「通过」或「打回」（验收评审为「通过」或「不通过」）；打回的 spec 退回 `待确认` 并由架构师修订后重新评审。编号 `NNN` 与对应 spec 一致。
