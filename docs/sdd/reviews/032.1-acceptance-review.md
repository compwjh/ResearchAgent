## 交给人工验收的可复现步骤

在可用网络与当前部署版本中，独立验收者至少应完成：

1. 启动服务并确认 `/api/health`、`/api/ready` HTTP 200，记录实际端口和启动命令。
2. 通过产品主路径点名 `usenix-catalog-orchestration`，限定 USENIX Security 2024；确认 `intent` 命中新 Skill，检索结果含服务端返回的 presentation 详情页 URL。
3. 对一篇摘要缺失候选调用 `fetch_paper_detail`，核对摘要非空且与官方详情页一致；确认全程未请求 PDF。
4. 对同一详情页重复调用，确认完成 FetchUnit 命中缓存、不重复发起网络请求，并记录限流/缓存证据。
5. 用一个可控失败详情页验证单页进入可重试失败，不影响其它论文和整体 job；记录稳定错误码及恢复结果。
6. 将上述请求、响应、论文 ID、详情 URL（脱敏后）、FetchUnit 状态、缓存命中和产物路径落盘，再由独立 tech-lead/tester 填写签字。

若真实外站、Ollama 或服务环境不可用，应记录具体命令、退出码和阻塞原因，保持 BLOCKED，不以 fixture、NDSS sync、provenance 查询或父规格 API 证据替代。
