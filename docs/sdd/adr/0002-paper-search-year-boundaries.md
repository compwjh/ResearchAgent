# 0002 论文检索年份双边界：校验边界与目录覆盖边界

Status: accepted

论文检索有两个互不相干的年份边界，混为一谈会让用户既搜不到又说不清原因：后端参数校验只接受 1900 至当年（越界直接 400），而 USENIX 实际只从 2022 起提供 accepted 目录——选 2010–2020 会顺利发起、必然零结果。我们决定把两者拆成两个独立概念：**年份校验边界**（用于拒绝请求，保持 1900–当前年不变）与**目录覆盖边界**（用于提示，由来源实际覆盖的最早年份决定，当前为 2022），后者不参与校验、只用于解释。

## Considered Options

- **把校验边界收紧到 2022**：彻底消除"静默零结果"，但改变了既有 API 语义、会牵动 `tests/test_paper_discovery_search.py` 的既有断言与其它调用方，且 DBLP 等来源的可用年份未必与 USENIX 一致，一刀切会误伤。
- **前端硬编码 2022**：改动最小，但来源一变就失真，且与后端不同步。
- **拆分两个边界，零结果由后端归因（选定）**：校验边界保持向后兼容，目录覆盖边界经 `paper_discovery/application` 受控入口暴露（硬边界禁止 `api` 直接 import `infrastructure`，而 2022 目前只存在于 infrastructure 层），结果接口在零结果时返回 `empty_reason`（`year_out_of_catalog` / `no_match` / `source_failed`），前端按因给不同文案。代价是多一个后端字段与一层受控入口。

## Consequences

- 用户选到 2022 之前不再被拦，但会看到"所选年份早于目录覆盖年份"的明确解释，而不是一个空列表。
- 目录覆盖边界必须经 application 暴露，不可在 `api` 层直连 infrastructure，也不能在前端写死；将来来源变化只需改一处。
- 年份校验边界（`min_year` / `max_year`）随 400 响应下发，前端不再硬编码"合法范围"文案。
- 零结果归因依赖后端判断，前端不得自行猜测原因；若后端无法归因，退化为中性文案而非谎报。
