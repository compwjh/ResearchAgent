# 006 - 修复左侧"模型库"Tab 点击无反应

- 状态：`已完成`
- 类型：Bug 修复（独立于功能 spec，目标/交互范围明确）
- 关联需求：无（独立缺陷）

## 一句话目标

点击左侧边栏"模型库"导航项时，应切换到一个模型列表视图并展示当前 Ollama 可用模型；当前点击无任何反应。

## 复现证据

- `frontend/index.html` 第 17 行：`<a class="nav-item" href="#models">模型库</a>` 指向不存在的 `#models` 视图。
- `frontend/app.js` 全局搜索：没有任何监听器处理 `.nav-item` 的点击事件，因此点击"模型库"不会发生视图切换，页面无变化（"没反应"）。
- 数据通道已存在：`app.js` 第 59–73 行 `fetch('/api/health')` 能拿到 `data.models` 数组并写入侧栏 `#model-count`；后端 `/api/health` 返回模型列表可用，无需改后端。

## 根因

前端缺少"模型库"视图的 DOM 容器与对应的导航切换逻辑。导航项只是 `#models` 锚点，既没有目标视图，也没有 JS 处理点击，导致无交互。

## 数据模型 / 展示字段（复用后端 health 数据）

| 字段 | 来源 | 说明 |
|---|---|---|
| name | `/api/health` 的 `models[]` | 模型名（如 `qwen2.5-coder:32b`） |
| active | `models.includes(data.model)` | 是否当前选中模型 |
| count | `models.length` | 侧栏角标已展示 |

## 端点 / 接口

- 复用已有 `GET /api/health`（返回 `{ model, models: [...] }`），不新增接口。
- 前端在切换"模型库"视图时，从已缓存的 `models` 渲染列表；若尚未加载则重新 `fetch('/api/health')`。

## 边界（每条之后会变成一条测试/验收点）

- 点击"对话"项应切回对话视图（导航高亮随当前视图变化）。
- 模型列表为空时显示"没有发现模型"占位，不报错。
- 点击列表中的某个模型，应将其设为当前模型（与对话区 `#model-select` 联动，更新 `activeModel` 与侧栏 `model-label`）。
- 重复点击"模型库"不重复添加 DOM / 不刷新抖动。
- 视图切换不触发对话区内容丢失（对话消息保留）。

## 明确不做

- 不新增后端接口（复用 `/api/health`）。
- 不做模型拉取/删除/下载管理（仅展示列表 + 选中）。
- 不改"对话"以外的其它导航项行为。

## 产品使用步骤（由产品经理在 spec 确认后填写）

- 步骤 1：用户点击左侧"模型库"导航项。
- 步骤 2：主区域切换为模型列表视图，展示 Ollama 可用模型（每行含模型名，当前选中模型有高亮标记）。
- 步骤 3：用户点击列表中某模型，该模型被设为当前模型，侧栏"本地服务"下的模型名同步更新，切回"对话"后对话区模型选择器显示该模型。
- 验收场景：点击"模型库"出现列表；点击其中模型后返回"对话"，发送消息时使用所选模型。
