# Spec 025 — 会话上下文压缩与 Token 预算管理（占位）

## 状态

**当前状态：待确认**

**阶段：占位待调研，不进入评审或实施。**

## 一句话目标

让长会话能够在保留关键事实、用户指令和可追溯依据的前提下压缩旧上下文，避免完整历史持续挤占模型上下文窗口。

## 已知问题

- 当前系统保存并装配会话历史，但没有真正的历史摘要替换、分段压缩或 token 预算管理。
- 模型可以建议用户新建会话，却不能替代平台完成持久历史的压缩。
- 长会话可能逐步增加首 token 延迟、输入成本并触达上下文上限。

## 待调研范围

- 原始消息、阶段摘要、长期记忆、项目指令和 RAG 证据之间的优先级。
- 压缩触发阈值、token 预算、可逆性、重建方式和用户可见性。
- 摘要错误、事实丢失、指令漂移以及跨项目隔离。
- 是否保留完整历史作为冷数据，以及模型调用只加载哪一层摘要。

## 数据模型

- 待后续专项调研；本占位不冻结字段、表或迁移。

## 端点 / 接口

- 待后续专项调研；本占位不承诺公开接口。

## 边界

- 后续设计必须保留项目隔离、SystemRule 优先级和完整历史的可追溯性。
- 压缩失败时不能丢失原始消息，也不能把一个项目的摘要注入另一个项目。

## 明确不做

- 本占位不创建 Task，不写数据模型或公开接口。
- 不修改业务代码，不清理现有会话，不影响 Spec024。
- 未重新进行需求讨论和确认前不得进入实现。
