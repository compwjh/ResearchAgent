## 一句话目标

将当前简单问答系统扩展为科研文章处理 Agent：Agent 先规范化用户问题并识别意图，只有识别为论文下载意图时，才自动检索文章元数据和可合法访问的下载来源，下载 PDF 到配置的本地目录，并向用户反馈检索、下载和校验结果。

## Agent 工作流

1. **问题规范化**：清理首尾空白、统一常见标点和空格，提取文章标题以及作者、年份、DOI 等辅助信息，生成结构化任务。
2. **意图识别**：根据规范化问题识别用户意图，至少支持 `download_paper`（下载论文）、`chat`（普通问答）和 `unsupported`（暂不支持）。
3. **意图路由**：仅当意图为 `download_paper` 且置信度达到阈值时，才进入文章检索分支；`chat` 进入现有 Ollama 对话分支；`unsupported` 返回澄清提示，不进入下载流程。
4. **检索候选**：按系统设置中的来源顺序请求检索地址，收集标题、作者、年份、DOI、摘要、文章页地址和 PDF 地址。
5. **候选排序**：优先匹配标题，其次参考作者、年份和 DOI；多个候选时向用户展示候选，不静默下载低置信度文章。
6. **选择合法来源**：优先使用开放获取、作者公开版本、机构仓储或用户配置的合法来源；来源需要明确返回可下载文件。
7. **登录分支**：如果候选来源需要用户登录，Agent 不尝试绕过登录，暂停自动下载并进入 Human-in-the-loop 节点；用户在浏览器中完成登录后，通过前端“已完成登录”操作通知 Agent 继续。
8. **下载与校验**：登录分支恢复后下载到配置目录，校验 HTTP 状态、内容类型、文件大小和 PDF 文件头，避免把 HTML 登录页或错误页保存为 PDF。
9. **结果记录**：保存文章元数据、来源地址、规范化问题、识别意图、登录分支状态、文件路径、下载时间、文件大小和校验结果，便于科研实验追溯。
10. **流式反馈**：前端展示规范化、意图识别、当前阶段、候选结果、登录提示、下载进度、成功结果或可操作的失败原因。

### 分支定义

- **入口节点：问题规范化**。所有用户输入必须先经过规范化，后续节点不得直接使用未清理的原始文本作为检索关键词。
- **路由节点：意图识别**。识别结果必须包含意图、置信度和规范化任务；低于阈值时要求用户澄清，不得猜测为下载论文。
- **普通问答分支**。识别为 `chat` 时进入现有 Ollama 对话流程，不调用文章检索和下载工具。
- **不支持分支**。识别为 `unsupported` 时返回当前支持范围和澄清提示，不创建下载任务。
- **第一分支：无需登录**。来源可公开访问，且候选匹配分数满足阈值；根据自动下载设置直接下载或请求用户确认。
- **第二分支：需要登录**。来源返回 401/403、登录页面或 Agent 判断必须登录；创建 Human-in-the-loop 等待节点，向用户展示目标网站和继续操作指引。用户完成登录后，Agent 重新检查来源访问状态，再继续下载。
- 用户未完成登录、登录超时或登录后仍无权限时，任务进入 `failed`，不得反复尝试或伪造下载成功。

## 数据模型

| 字段 | 类型 | 约束（必填？范围？默认？）|
|---|---|---|
| `query` | string | 必填；去除首尾空白；长度 1-500；至少包含文章名称 |
| `normalized_query` | string | 问题规范化节点输出；必填；用于意图识别和后续路由 |
| `intent` | enum | `download_paper` / `chat` / `unsupported` |
| `intent_confidence` | number | 0-1；低于阈值时必须请求澄清，不得进入下载分支 |
| `authors` | string[] | 可选；来自检索结果或用户输入 |
| `year` | integer | 可选；1900-当前年份 |
| `doi` | string | 可选；保留标准 DOI 文本 |
| `title` | string | 检索结果必填 |
| `article_url` | string | 可选；必须是有效 HTTP(S) URL |
| `pdf_url` | string | 下载时必填；必须是有效 HTTP(S) URL |
| `source_name` | string | 必填；来源名称 |
| `source_kind` | enum | `open_access` / `repository` / `configured` |
| `confidence` | number | 0-1；低于确认阈值时不得自动下载 |
| `requires_login` | boolean | 由来源响应或人工判断得到；为 `true` 时必须进入 Human-in-the-loop 分支 |
| `human_action` | enum | `not_required` / `waiting_login` / `login_completed` / `login_failed` |
| `download_dir` | string | 系统设置必填；必须是本地可写目录，默认项目数据目录 |
| `filename` | string | 由标题和唯一标识生成；清理路径分隔符和危险字符 |
| `file_path` | string | 下载成功后返回的本地路径 |
| `file_size` | integer | 下载成功后必填；大于 0 |
| `checksum` | string | 下载成功后生成，用于重复文件识别和实验追溯 |
| `status` | enum | `searching` / `awaiting_selection` / `downloading` / `completed` / `failed` |
| `error` | string | 失败时必填；不得泄露凭据 |

## 系统设置

第一版通过 Agent 系统设置配置以下内容；设置界面可以后续补充，初版至少提供后端配置接口或环境变量读取能力：

| 设置 | 说明 | 默认行为 |
|---|---|---|
| `article_search_urls` | 文章检索地址列表，按顺序尝试；支持 HTTP(S) | 未配置时使用内置公开来源策略，若没有可用来源则明确报错 |
| `article_download_urls` | 下载地址或下载来源列表；支持 HTTP(S) | 未配置时使用检索结果中的合法 PDF 地址 |
| `article_download_dir` | 本地下载目录 | 项目数据目录下的 `data/articles` |
| `article_auto_download` | 是否在高置信度且来源合法时自动下载 | `false`，默认先展示候选并等待确认 |
| `article_match_threshold` | 自动选择候选的最低匹配分数 | `0.90` |
| `article_max_file_size_mb` | 单文件最大下载大小 | `100` |
| `article_request_timeout_seconds` | 单次请求超时 | `30` |
| `article_login_timeout_seconds` | 用户完成登录的最长等待时间 | `300` |

配置中的地址只能用于正常 HTTP(S) 请求。需要认证的地址通过服务器端环境变量或安全配置提供，不能在前端回显或写入日志。

## 端点 / 接口

| 动作 | 输入 | 成功返回 | 失败情况（状态码）|
|---|---|---|---|
| `POST /api/agent/articles/search` | `{ query, authors?, year?, doi? }` | Agent 任务 ID、阶段状态、候选文章列表和匹配分数 | `400` 输入无效；`502` 检索来源不可用；`504` 超时 |
| `POST /api/agent/run` | `{ query, model?, mode? }` | 流式返回规范化、意图识别和对应分支事件；仅 `download_paper` 意图进入文章下载流程 | `400` 输入无效；`409` 意图置信度不足需澄清；`502` 下游服务不可用 |
| `POST /api/agent/articles/download` | `{ candidate_id, task_id? }` | 流式事件：阶段、进度、文件路径、元数据、校验结果；需要登录时返回 `waiting_login` 事件并暂停 | `400` 候选无效；`401` 需要登录；`403` 来源不可访问；`404` 文件不存在；`413` 超过大小限制；`502` 下载失败 |
| `POST /api/agent/tasks/{task_id}/human-actions/login-completed` | `{ candidate_id }` | 标记用户已完成登录，恢复任务并重新检查来源访问状态 | `400` 任务状态不允许继续；`404` 任务或候选不存在；`408` 登录等待超时；`403` 登录后仍无权限 |
| `GET /api/agent/settings` | 无 | 返回非敏感配置和来源名称；不返回密钥 | `500` 配置读取失败 |
| `PUT /api/agent/settings` | `{ article_search_urls?, article_download_urls?, article_download_dir?, article_auto_download?, ... }` | 返回校验后的配置 | `400` URL、目录或数值范围无效；`409` 目录不可写 |
| `GET /api/agent/tasks/{task_id}` | 任务 ID | 返回当前状态、候选、下载记录和错误信息 | `404` 任务不存在 |

流式接口继续使用 SSE。事件至少包括：`meta`、`normalized`、`intent`、`stage`、`candidate`、`human_action_required`、`progress`、`result`、`error`、`done`。`intent` 事件必须包含识别结果和置信度；`human_action_required` 事件必须包含任务 ID、候选 ID、目标来源名称、等待状态和过期时间，不得包含密码、Cookie、Token 或其他敏感凭据。

## 边界（每条之后会变成一条测试）

- 输入为空、只有空格、超过 500 字符。
- 规范化前后文本为空、连续空格和标点、混合中英文标点、文章标题附带作者/年份/DOI。
- 意图明确为下载论文、明确为普通问答、无法识别意图、意图置信度刚好低于阈值；普通问答不得触发检索或下载。
- 输入是模糊标题、标题包含特殊字符、标题中带作者或 DOI。
- 没有候选、候选多个且分数接近、候选低于自动匹配阈值。
- 检索地址为空、重复、格式非法、不是 HTTP(S)、返回超时或返回非预期 JSON。
- 来源要求登录、返回登录页面、登录完成通知重复提交、登录等待超时或登录后仍无权限。
- PDF 地址重定向到不允许的协议、返回 HTML、返回非 PDF 内容、文件为空或超过大小限制。
- 下载目录不存在、不可写、路径包含 `..` 或文件名包含路径分隔符。
- 同一篇文章重复下载时复用或覆盖策略必须明确，不能产生不可追踪的重复文件。
- 下载中断、网络断开、来源返回 401/403/404/429/5xx。
- Agent 任务被重复提交、任务 ID 不存在、前端刷新后查询任务状态。
- Human-in-the-loop 节点等待期间前端刷新或断开后，任务仍可通过任务 ID 查询并继续；用户只能继续自己有权限的等待任务。
- 配置包含敏感信息时，日志、SSE 和 API 响应不得返回凭据。
- 不配置来源时，Agent 必须明确说明没有可用检索/下载来源，不能伪造成功。

## 验证方式

- 单元测试：标题解析、候选匹配排序、URL 校验、文件头校验、文件名清理、配置校验和重复下载判断。
- 单元测试：问题规范化、意图识别分类、置信度阈值和分支路由；验证 `chat` 与 `unsupported` 不会调用文章下载工具。
- 接口测试：覆盖搜索、候选确认、下载、配置读写、任务查询及上述错误状态码。
- 集成测试：使用本地 mock 检索服务和 mock PDF 服务，不依赖真实论文网站；验证完整 Agent 状态流转和 SSE 事件顺序。
- 集成测试：使用 mock 登录来源验证 `waiting_login` → 用户确认登录 → 重新检查权限 → 下载校验的状态流转。
- 前端测试：输入普通问题时进入聊天分支；输入文章下载请求时展示规范化和意图识别状态，再展示候选、确认下载、登录提示、进度/错误/完成结果；模型选择和原有普通聊天能力不能回归。
- 安全检查：禁止任意文件路径写入、禁止非 HTTP(S) 下载、限制文件大小、敏感配置不回显。
- 人工验收：输入一篇已知开放获取文章，能看到元数据、来源、下载进度、最终文件路径和校验信息。

## 明确不做（划出范围，防 AI 自由发挥）

- 不绕过付费墙、登录限制、验证码、访问控制或版权保护措施。
- 不代替用户输入密码、处理验证码或窃取、保存、回显 Cookie、Token 等登录凭据；Human-in-the-loop 只负责等待用户完成登录并继续任务。
- 不自动抓取或批量下载未明确配置且不具备合法公开访问条件的网站内容。
- 不在第一版实现 PDF 全文解析、向量化、知识库问答、引用生成或实验结论分析。
- 不在第一版实现复杂的多用户权限、云端文件存储、后台队列集群或断点续传。
- 不替换现有 Ollama 模型能力；Agent 的规划与工具调用基于现有 LangGraph 体系扩展。
- 不默认自动下载低置信度候选；候选不明确时必须要求用户选择。

## 意图识别修订 Errata（已实施）

> 本小节是对本 spec「意图识别」节点的修订，原 001 实现的 `classify_intent()` 为纯关键词匹配，存在缺陷，需改为大模型判断、并以 `chat` 为兜底。

### 缺陷（实测）

`backend/app/agents/article_agent.py` 的 `classify_intent()` 仅做关键词匹配：`DOWNLOAD_WORDS`/`CHAT_WORDS` 词表 + 英文标题启发式。用户输入「生成一个300字的小故事」不含任何触发词、无 ≥2 个大写英文词 → 落入 `return "unsupported", 0.45` → `run_agent` 返回"暂时无法识别该请求"。一个明显属于普通问答的请求被错误拒绝。

### 修订方案

- **用大模型判断意图**：新增轻量意图分类调用（建议可配置快速对话模型，默认 `qwen3.5:9b`），提示词要求模型输出结构化 JSON：`{"intent": "download_paper" | "chat", "confidence": 0~1}`，并明确"普通问答、创作、解释、闲聊、写代码/写文案等默认归为 chat；仅当用户明确要下载/获取某篇论文时才归为 download_paper"。
- **`chat` 为兜底分支**：模型输出无法解析、置信度过低、调用失败、或返回非预期值时，**一律回退为 `chat`**（不再回退到 `unsupported`，不再返回"无法识别"澄清语）。
- **移除 `unsupported` 路由分支**（对原 001 的偏离，需确认）：`run_agent` 中仅 `download_paper` 进入检索/下载，其余（含原 `unsupported`）统一走 `chat` 分支。即 `chat` 取代 `unsupported` 成为兜底。
- **可选快速短路（性能优化）**：若输入命中强下载触发词（如"下载论文"/"download paper"），可直接判 `download_paper` 并跳过模型调用；其余一律交给模型，避免再出现漏匹配。
- 意图事件 `intent` 仅对 `download_paper` 携带 `skill`（沿用 005）；`chat` 不带 `skill`。

### 对原 001 内容的影响

- 原 §2/§3、`分支定义` 的"不支持分支"、数据模型 `intent` 枚举（`download_paper`/`chat`/`unsupported`）需相应修订：`unsupported` 退出路由结果，仅作为模型极偶然的显式返回且仍回退 `chat`。
- `run_agent` 删除 `task.intent == "unsupported"` 分支，`else` 走 `chat`。
- `tests/test_api.py::test_run_emits_intent_events` 原断言 `"intent": "unsupported"`（输入"帮我处理实验数据"）→ 改为断言 `chat`（大模型判断普通请求 → chat）。

### 边界（逐条成测）

- 「生成一个300字的小故事」「帮我解释一下 Transformer」等普通请求 → `chat`，绝不进入下载流程。
- 明确下载请求（"下载论文 Attention is all you need"等）→ `download_paper`，并按 005 携带 `skill`。
- 意图模型异常 / 超时 / 返回非 JSON / 置信度缺失 → 回退 `chat`，不返回 500、不返回 unsupported 澄清语。
- `chat` 不得触发文章检索或下载（沿用 001 既有约束）。

### 验证

- 单测 + API 测试覆盖上述边界；`test_run_emits_intent_events` 改为 `chat` 后通过。
- 运行时验证：服务启动后，前端发送「生成一个300字的小故事」「帮我写一首诗」「解释下注意力机制」均进入普通问答；发送"下载论文 …"进入下载流程并带 skill 提示。
- 回归：现有 39 条测试（含 004/005）继续通过；前端 JavaScript 语法检查通过。
