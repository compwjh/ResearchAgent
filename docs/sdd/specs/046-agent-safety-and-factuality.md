## 数据模型

- **任务授权范围**：由服务端保存的用户目标、允许能力和资源约束。网页、PDF、工具结果、历史记忆及模型生成文字均不能授予或扩大本次动作权限。
- **拟执行动作与单次授权**：由服务端绑定所有者、任务、工具、规范化参数及目标摘要，具有待确认、允许、拒绝、失效、已消费等明确状态。确认、参数变更、取消和并发重试的状态转换由技术门禁冻结。动作结果或执行凭据用于判断是否可安全重试。
- **防护事件**：独立的 `guard-event-v1` 公共投影。含稳定事件 ID、请求及可用的消息／步骤／任务关联、模块、阶段、状态、原因码、实际模型及策略版本、耗时、白名单计数与授权可见证据定位。明确区分执行完毕、拦截、失败和跳过。与 Spec044 的 `step-evidence-v1` 并存。
- **事实核验结果**：原子命题、证据支持／矛盾／不足／不可核验、受权限约束的证据定位，以及最终回答的核验范围。未核验草稿与最终回答分开。
- **训练与评测清单**：`guard-model-manifest-v1` 固定角色、基础模型和 tokenizer 版本、数据及分割指纹、训练参数与日志、产物哈希、评测引用。 `security-benchmark-v1` 固定环境、样本、评分器、配置、结果及失败统计。存储及校验细节在技术门禁冻结。

## 端点与接入

| 动作 | 输入与输出 | 失败或恢复 |
|---|---|---|
| 聊天与深度研究执行 | 复用现有对话入口、ToolLoop 原生与 JSON 分发、研究运行时及 worker。真正调用前执行同一授权契约 | 硬规则拒绝、等待合法授权或核验失败均有可观察结果。未接入路径不直接执行高风险动作 |
| 任务内单动作确认 | 复用原会话或研究任务上下文，提交服务端动作引用及用户选择 | 越权访问遵循已有资源隐藏策略。过期、参数变更、取消和已消费请求不能触发新执行 |
| 事实核验问答 | 普通问答继续流式。主动选择核验或报告流程明确启用后，先发真实进度，再发布正文与证据状态 | 部分核验、未核验与证据不足分开。关键证据缺失的报告保留已有结果并标记部分完成 |
| 防护事件读取 | 对话 SSE 和持久化历史读取共享安全投影，研究复用已有时间线。优先复用历史接口，需独立读取时采用消息或任务归属下的有界列表 | 重连不重复，不从终态倒退。无持久化会话仅展示本次。未知事件安全降级 |
| 训练、评测与 README | 离线 CLI 执行并生成版本化清单，审核后从清单更新 README 受控区 | 无数据写未测试，版本不同或分割污染禁止计算跨组增益，结果生成器支持只校验模式 |

新增确认端点的具体路径、状态码及读写契约，核验选项的请求字段，以及事件水合载体在 Gate 2 冻结。Scope 内至少核对现有普通对话、直接聊天、知识库问答、文章助手和研究工具，逐项记录覆盖、跳过或禁止的动作。

## 边界

- **服务端授权**：已有 schema、权限、SSRF、沙箱和内容安全约束始终生效。联网、下载、导入、写入、外发等 Agent 动作须校验实际参数和目标；检查异步、重定向、重试、批次及可直接调用的分发入口。4B 的判断无权放宽规则。
- **生产开关**：管理员可独立切换模型检测及事实核验。必须经过模型核验的敏感动作在能力关闭、故障或超时时停止。弱化配置只用于隔离评测。任务保留策略版本，但执行前仍校验当前权限是否撤销。
- **授权与重试**：违反硬规则或超出任务范围的动作直接阻止。只对硬规则允许、处于任务范围且缺少授权的单个动作发起确认。参数变化使旧确认失效。校验重复确认、并发、取消及结果未知的重试，已成功的副作用不得重放。
- **RAD 适配**：单独的受控检索数据与版本化阈值，使用独立验证集校准并覆盖正常学术安全问题。标签概率不可取得时采用可校准的替代输出并披露差异。业务文档或用户输入不得自动进入检索或训练集。
- **MARCH 式核验**：Checker 只看中性问题和已授权检索证据，不接收 Solver 答案、结论数字或隐藏推理。独立回答由比较阶段与原命题核对。引用存在与语义支持分别检查，修订后新增或改写的事实重新验证；总命题数、耗时、轮次均有上限。
- **发布与草稿**：证据不足优先显示可支持部分与证据缺口。只有主动开启核验的问答可展开未核验草稿，且草稿先过输出安全检查，不显示密钥或已拦截内容。正式回答与引用只保存发布版本。
- **事件隐私**：按消息／任务所有者读取，删除所属资源时清理事件，沿用项目留存规则。前端和 Langfuse 只收白名单投影，不携带攻击原文、敏感资料、凭据或隐藏推理。观测故障不改变安全决策。
- **本机资源**：M3 Max 36GB 上离线复训 DeBERTa-v3-base 二分类器。推理限制并发及队列，双模型常驻须经实测。记录加载及排队耗时、失败、峰值统一内存和 swap。缩短序列与减小批次后仍不稳定，记录第二次交付阻塞。普通问答可明确降级，辅助模型不接管最终回答。
- **统计与发布**：固定 27B、题目、语料、工具权限、采样和评分规则。保留既有执行防护、执行防护加官方 PIGuard、执行防护加本机复训 PIGuard 三组，后两组仅替换检测器权重，安全和事实性结果分开。报告样本及有效数、攻击成功率、误拒率、任务完成率、延迟、故障率及证据核验质量。故障不得当成成功防御，基线为零时相对降幅不适用。
- **数据隔离与上线**：许可明确的替代集可用于公开项目对照，标注与论文配置的差异。按文档与攻击家族隔离训练、检索、调参与最终评测。用独立验证集先确定上线门槛，再看最终测试。实验可在结果持平或退步时如实验收，默认启用须另行通过所有门槛。

## 产品使用步骤与验证

1. **第一次自然语言验收**：从聊天发起经许可的隔离测试来源论文检索和下载。查看真实授权检查、必要时确认一个明确动作，等待下载结束。重复同题并切换含注入的测试来源。验证越权目标未收到动作、页面解释原因，并根据真实任务状态提示可继续或重试。刷新后核对事件历史。
2. **第二次核验验收**：在有索引论文的问答里主动启用核验并提问。等待真实核验进度，查看发布正文、证据跳转和证据缺口。用受控冲突案例验证修订或部分完成，再核对实际 4B 与 27B 角色和模型版本。
3. **独立实验验收**：用隔离公开基准跑配对对照，并用业务测试执行真实端到端。保留请求、响应、事件 ID、动作执行证据、部署版本、模型及产物哈希、报告位置和 README 校验结果。
4. 每次部署里程碑须有真实 API E2E 与浏览器证据；交人工前提供逐步点击、提示、等待、恢复和产物路径，达到准备度 9/10 且无 P0/P1。Spec 最终候选运行全量回归。

- **加载和部署**：按清单固定 tokenizer、架构、权重哈希、标签映射、推理长度及策略版本。将已核验的本机 state dict 离线转换为 safetensors，校验转换前后同输入分类一致。运行时使用本地、显式配置的权重路径及审查过的模型代码，关闭远程代码执行和自动下载。服务启动时严格校验参数结构与哈希，记录就绪或不可用状态。默认关闭，通过验收后单独决定启用。权重、训练数据和完整断点放在 Git 外。
- **运行契约**：对网页、PDF、工具结果等外部内容，保留来源标识，按有界窗口处理长文本，单窗口按官方推理口径最多 256 token。输出 `benign=0` 或 `injection=1`、分数、来源定位及模型版本。记录截断、超时及未覆盖窗口。检测结果进入既有防护策略和事件，服务端继续独立核对动作授权。模型故障按现有规则降级，敏感动作需要的检查无法完成时暂停该动作。
